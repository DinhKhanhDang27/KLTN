Tổng quan lab

Vì đây là pipeline (không handshake bus), interface mang clk/rst, các tín hiệu quan sát từng tầng, và quan trọng nhất: cổng retire (RVFI-lite) tái dựng "lệnh nào vừa commit ở tầng WB" — vì pipeline không mang PC/instruction xuống tới WB.

  • Lab sau dùng để làm gì: Lab 3 (driver) gọi backdoor nạp chương trình + điều khiển reset; Lab 4 (monitor) sample ret_cb dựng transaction retire; mọi component nhận interface này dưới dạng virtual interface qua config_db.
Trọng tâm UVM của lab
  • Virtual interface là cầu nối duy nhất giữa thế giới module (tĩnh, có clock) và thế giới class (động, UVM) — mọi driver/monitor sau này đều nhận nó qua uvm_config_db.

3. Mục tiêu học

  • Hiểu vì sao verify CPU pipeline là white-box: core chỉ lộ out_pc/ out_alu_result (tầng IF/EX) — muốn "chấm điểm" phải nhìn writeback ở WB + bộ nhớ.
  • interface gom tín hiệu quan sát; clocking block chống race khi sample.
  • modport giới hạn hướng cho monitor (chỉ đọc) và driver (lái reset + backdoor).
  • Hierarchical reference (đi lên từ interface: dut....) để nạp ROM, đọc trộm regfile/data-mem, và đọc tín hiệu nội bộ từng tầng pipeline.
  • Shadow pipeline (RVFI-lite): tái dựng "dòng commit" — mỗi lệnh thật đúng 1 sự kiện retire theo thứ tự chương trình, kể cả khi có bubble/flush. KHÔNG sửa DUT.
  • Chạy mô phỏng đầu tiên bằng xvlog/xelab/xsim (chưa có UVM).

6. Lý thuyết UVM — ranh giới TB ↔ DUT

6.1. Hai thế giới: module vs class

UVM component là class: được tạo lúc runtime (type_id::create), không có port, không nằm trong cây instance của elaboration. DUT và interface là module/interface: tồn tại tĩnh từ lúc elaborate. Một class không thể khai báo riscv_if vif(); — nó chỉ có thể giữ một con trỏ tới interface đã tồn tại: virtual riscv_if vif;. Đó là toàn bộ lý do virtual interface tồn tại.

// top (module-world)                          // driver (class-world)
riscv_if vif(.clk(clk));                       virtual riscv_if vif;     // handle, mặc định null
initial uvm_config_db#(virtual riscv_if)       function void build_phase(uvm_phase phase);
          ::set(null, "*", "vif", vif);          if (!uvm_config_db#(virtual riscv_if)::get(this,"","vif",vif))
                                                   `uvm_fatal("NOVIF", "vif chua duoc set")

6.2. Race condition & regions — vì sao cần clocking block

Trong một time-step, simulator chạy các region theo thứ tự: Preponed → Active → Inactive → NBA → Observed → Reactive → Postponed. DUT (RTL) cập nhật bằng <= ở NBA; nếu TB đọc/ghi bằng blocking ở Active ngay sườn clock, kết quả phụ thuộc thứ tự thực thi → race.

6.3. modport, clocking block và config_db — cái bẫy kinh điển

modport chỉ là view kiểm tra hướng tín hiệu lúc compile; nó không phải member của interface instance. Vì vậy vif.mon.ret_cb hay vif.drv.rst là cú pháp sai — clocking block là member trực tiếp: vif.ret_cb. Bộ lab dùng virtual riscv_if trơn (không chọn modport ở handle):

// SAI: kiểu khác nhau → config_db tìm không ra (lookup theo type của T)
virtual riscv_if.mon vif_m;
uvm_config_db#(virtual riscv_if.mon)::get(this,"","vif",vif_m);   // top set bằng virtual riscv_if → get trả 0

// ĐÚNG (pattern AXI VIP & phần lớn VIP thương mại): handle trơn, phân quyền bằng clocking block
virtual riscv_if vif;
@(vif.ret_cb);  if (vif.ret_cb.ret_valid) ...
Bẫy: uvm_config_db#(T) khớp theo kiểu T chính xác. virtual riscv_if và virtual riscv_if.mon là hai kiểu khác nhau → get() trả 0, không có lỗi compile, chỉ NOVIF lúc chạy.

6.4. Backdoor trong interface (BFM pattern)

Các task load_instr/peek_reg/peek_mem đặt trong interface để class chỉ gọi vif.peek_reg(5) mà không biết đường dẫn RTL — đường dẫn hierarchical bị “nhốt” vào một file. Nhược điểm: interface phải biết module cha có instance tên dut. Ta viết dut.u_imem.mem[...] (upward name resolution — SV tìm dut ở module chứa interface instance) thay vì path tuyệt đối riscv_tb_top.dut..., vì path tuyệt đối chỉ chạy với đúng một harness (Lab 3/4/9 dùng harness tên khác riscv_drv_tb/riscv_mon_tb/… → 'riscv_tb_top' is not declared). Giải pháp công nghiệp: truyền đường dẫn bằng string rồi dùng uvm_hdl_read/uvm_hdl_deposit (DPI, hỗ trợ trong UVM) — Lab 13 sẽ quay lại.

Debug: Chạy với +UVM_CONFIG_DB_TRACE để thấy từng lệnh set/get vif (ở Lab 5 trở đi). Nếu get fail, kiểm tra: (1) đúng kiểu, (2) scope string, (3) set chạy trước build_phase của component get.
RISC-V recap: pipeline 5 tầng, hazard, vì sao phải dựng retire (bạn đã biết — mở nếu cần)
  1. 5 tầng: IF (fetch) → ID (decode, đọc reg) → EX (ALU, quyết định rẽ nhánh) → MEM (truy cập data mem) → WB (ghi regfile). Regfile ghi ở negedge (write-first cho ID).
  2. Hazard: forwarding EX/MEM, MEM/WB → EX; load-use stall 1 chu kỳ; rẽ nhánh/nhảy quyết ở EX → flush IF/ID + ID/EX (lệnh đã fetch sai bị hủy, ifid_valid=0).
  3. Vì sao phải tái dựng retire? RTL mang field giải mã xuống pipeline nhưng không mang PC và instruction gốc tới MEM/WB. Muốn có bản ghi retire đầy đủ (pc, instr, rd, wb_data, mem) ta dựng shadow pipeline trong top: mảng reg song song đi theo đúng điều kiện bubble/flush của DUT. Đây chính là ý tưởng của RVFI (RISC-V Formal Interface) — cổng trace lúc commit.
  4. Vì sao backdoor? Core fetch lệnh từ ROM. Để UVM điều khiển chương trình, ghi thẳng dut.u_imem.mem[idx] bằng hierarchical reference — tức thì, không tốn chu kỳ.
  5. Reset: active-high, PC về 0 ở posedge rst. TB giữ rst=1 vài chu kỳ rồi nhả; cần ~5 chu kỳ để lệnh đầu tiên "chảy" tới WB.

// tb/if/riscv_if.sv — ranh giới UVM ↔ core RISC-V 5-stage pipeline
`ifndef RISCV_IF_SV
`define RISCV_IF_SV

interface riscv_if (input logic clk);

  // ---- Tín hiệu điều khiển TB lái ----
  logic        rst = 1'b1;       // active-high; giữ reset cho tới khi driver nhả

  // ---- Probe thô theo tầng (top assign từ net nội bộ DUT) ----
  logic [31:0] pc_if;            // dut.pc_if         (PC tầng IF)
  logic [31:0] alu_result_ex;    // dut.alu_result_ex (ALU tầng EX)
  logic        stall;            // dut.stall         (load-use stall)
  logic        redirect;         // dut.redirect      (branch/jump taken ở EX)

  // ---- CỔNG RETIRE (RVFI-lite): mô tả lệnh vừa commit ở WB ----
  logic        ret_valid;        // 1 = có 1 lệnh thật commit chu kỳ này
  logic [31:0] ret_pc;           // PC của lệnh commit
  logic [31:0] ret_instr;        // instruction word gốc
  logic        ret_reg_write;    // ghi regfile?
  logic [4:0]  ret_rd;           // thanh ghi đích
  logic [31:0] ret_wb_data;      // dữ liệu writeback
  logic        ret_mem_write;    // store?
  logic [31:0] ret_mem_addr;     // địa chỉ store
  logic [31:0] ret_mem_wdata;    // dữ liệu store

  // ---- Clocking block cho MONITOR: chỉ sample, chống race ----
  clocking ret_cb @(posedge clk);
    default input #1step;
    input ret_valid, ret_pc, ret_instr, ret_reg_write, ret_rd, ret_wb_data;
    input ret_mem_write, ret_mem_addr, ret_mem_wdata;
    input pc_if, alu_result_ex, stall, redirect;
  endclocking

  // ---- Modport ----
  modport mon (clocking ret_cb, input clk, input rst);
  modport drv (input clk, output rst);   // driver cầm reset + gọi backdoor

  // ======================================================================
  //  BACKDOOR HOOKS — hierarchical reference tới DUT.
  //  `dut` được tìm ĐI LÊN từ interface instance, nên chạy với mọi harness (riscv_tb_top, riscv_drv_tb, ...)
  //  miễn là module chứa interface cũng có instance tên `dut`.
  // ======================================================================

  // Ghi 1 lệnh vào ROM tại word-index idx (= địa chỉ byte >> 2).
  task automatic load_instr(input int idx, input logic [31:0] data);
    dut.u_imem.mem[idx] = data;
  endtask

  // Nạp cả file hex (mỗi dòng 1 word theo chuẩn $readmemh).
  task automatic load_hex(input string path);
    $readmemh(path, dut.u_imem.mem);
  endtask

  // Xóa ROM về NOP (addi x0,x0,0 = 0x00000013) để chương trình sạch.
  task automatic clear_imem(input int n = 1024);
    for (int i = 0; i < n; i++) dut.u_imem.mem[i] = 32'h00000013;
  endtask

  // Đọc trộm 1 thanh ghi (x0..x31). x0 luôn 0.
  function automatic logic [31:0] peek_reg(input int r);
    if (r == 0) return 32'd0;
    return dut.u_regfile.registers[r];
  endfunction

  // Đọc trộm 1 word data memory tại địa chỉ byte (căn chỉnh 4).
  function automatic logic [31:0] peek_mem(input int byte_addr);
    int b; b = byte_addr & 11'h7fc;
    return {dut.u_dmem.mem[b+3], dut.u_dmem.mem[b+2],
            dut.u_dmem.mem[b+1], dut.u_dmem.mem[b]};
  endfunction

endinterface
`endif

// tb/top/riscv_tb_top.sv — top mô phỏng Lab 1 (chưa có UVM)
`timescale 1ns/1ps

module riscv_tb_top;

  logic clk = 0;
  always #5 clk = ~clk;          // chu kỳ 10ns

  // Interface
  riscv_if vif (.clk(clk));

  // DUT: pipeline, cùng ports như single-cycle riscv_top
  riscv_pipeline_top dut (
    .clk            (clk),
    .rst            (vif.rst),
    .out_pc         (),
    .out_alu_result ()
  );

  // ---- Probe thô ----
  assign vif.pc_if         = dut.pc_if;
  assign vif.alu_result_ex = dut.alu_result_ex;
  assign vif.stall         = dut.stall;
  assign vif.redirect      = dut.redirect;

  // ======================================================================
  //  SHADOW PIPELINE — tái dựng retire mà KHÔNG sửa DUT.
  //  Mỗi tầng ta giữ song song: valid + pc + instr, đi theo đúng điều kiện
  //  bubble/flush của riscv_pipeline_top.
  //    insert_bubble(ID/EX) = redirect | stall   (rst xử lý ở nhánh reset)
  //    EX/MEM luôn tiến (top dùng bộ nhớ single-cycle, không có mem_stall)
  //  Thông tin store của lệnh đang ở MEM (dut.exmem_*) được chốt sang MEM/WB.
  // ======================================================================
  logic        s_idex_valid,  s_exmem_valid,  s_memwb_valid;
  logic [31:0] s_idex_pc,      s_exmem_pc,     s_memwb_pc;
  logic [31:0] s_idex_instr,   s_exmem_instr,  s_memwb_instr;
  logic        s_memwb_mwrite;
  logic [31:0] s_memwb_maddr,  s_memwb_mwdata;

  always @(posedge clk or posedge vif.rst) begin
    if (vif.rst) begin
      s_idex_valid  <= 1'b0;
      s_exmem_valid <= 1'b0;
      s_memwb_valid <= 1'b0;
    end else begin
      // --- ID/EX: mirror idex_valid_r ---
      s_idex_valid <= (dut.redirect | dut.stall) ? 1'b0 : dut.ifid_valid;
      s_idex_pc    <= dut.ifid_pc;
      s_idex_instr <= dut.ifid_instr;
      // --- EX/MEM: luôn tiến ---
      s_exmem_valid <= s_idex_valid;
      s_exmem_pc    <= s_idex_pc;
      s_exmem_instr <= s_idex_instr;
      // --- MEM/WB: chốt cả thông tin store của lệnh vừa qua MEM ---
      s_memwb_valid  <= s_exmem_valid;
      s_memwb_pc     <= s_exmem_pc;
      s_memwb_instr  <= s_exmem_instr;
      s_memwb_mwrite <= dut.exmem_mem_write;
      s_memwb_maddr  <= dut.exmem_alu_result;
      s_memwb_mwdata <= dut.exmem_store_data;
    end
  end

  // ---- Lái cổng retire của interface (tổ hợp, ở tầng WB) ----
  assign vif.ret_valid     = s_memwb_valid;
  assign vif.ret_pc        = s_memwb_pc;
  assign vif.ret_instr     = s_memwb_instr;
  assign vif.ret_reg_write = dut.memwb_reg_write_r;
  assign vif.ret_rd        = dut.memwb_rd_r;
  assign vif.ret_wb_data   = dut.memwb_wb_value_r;
  assign vif.ret_mem_write = s_memwb_mwrite;
  assign vif.ret_mem_addr  = s_memwb_maddr;
  assign vif.ret_mem_wdata = s_memwb_mwdata;

  // ---- Smoke test: nạp chương trình, nhả reset, in mỗi lần retire ----
  initial begin
    vif.rst = 1'b1;
    vif.clear_imem();
    // addi x1,x0,5 ; addi x2,x1,3 ; add x3,x1,x2 ; jal x0,0 (loop)
    vif.load_instr(0, 32'h00500093);
    vif.load_instr(1, 32'h00308113);
    vif.load_instr(2, 32'h002081b3);
    vif.load_instr(3, 32'h0000006f);
    repeat (2) @(posedge clk);
    vif.rst = 1'b0;

    repeat (12) @(posedge clk) begin
      if (vif.ret_valid)
        $display("[%0t] RETIRE pc=0x%08h instr=0x%08h rw=%b rd=x%0d wb=0x%08h",
                 $time, vif.ret_pc, vif.ret_instr, vif.ret_reg_write, vif.ret_rd, vif.ret_wb_data);
    end

12. Phỏng vấn — hỏi & đáp mẫu

Bấm câu hỏi để xem đáp án — nên tự trả lời miệng trước khi mở. Mỗi câu có ví dụ cụ thể như khi bị hỏi trong phỏng vấn.

Virtual interface là gì? Vì sao class không khai báo thẳng interface được?

Ý chính: virtual interface là handle (con trỏ) tới một interface instance tĩnh đã tồn tại. Class sinh ra lúc runtime nên không thể “chứa” một instance tĩnh (có port, có clock) — chỉ trỏ được.

module top;  riscv_if vif(.clk(clk));                    // instance thật, elaboration-time
  initial uvm_config_db#(virtual riscv_if)::set(null,"*","vif",vif);  // đưa con trỏ vào DB
endmodule
class riscv_driver extends uvm_driver#(riscv_seq_item);
  virtual riscv_if vif;                                   // chỉ là handle; null cho tới khi get()
endclass

Nếu quên get, vif = null → null-pointer dereference ở lần dùng đầu tiên (xsim: lỗi runtime, không phải compile).

Giải thích race giữa TB và DUT và cách clocking block loại bỏ nó. Cho ví dụ.

Ví dụ race: monitor viết @(posedge clk) if (vif.ret_valid) .... ret_valid do RTL cập nhật bằng NBA ở cùng sườn. Monitor ở Active có thể đọc giá trị cũ (trước NBA) hoặc mới — tùy thứ tự lập lịch của simulator → kết quả khác nhau giữa xsim/VCS hoặc khi đổi thứ tự file.

Clocking block với default input #1step lấy mẫu ở Preponed — giá trị ổn định ngay trước sườn → tất định. Với output, drv_cb.sig <= v lái sau sườn (output skew), giống hệt hành vi flop thật. Quy tắc nhớ: TB lái và lấy mẫu qua clocking block, không bao giờ truyền thẳng tín hiệu ở sườn clock.

virtual riscv_if.mon vif; có vấn đề gì khi dùng với uvm_config_db? Công ty bạn xử lý ra sao?

config_db là kho key/value có kiểu tham số hóa: set(... virtual riscv_if ...) và get(... virtual riscv_if.mon ...) là hai kiểu khác nhau → get trả 0, test chết bằng UVM_FATAL NOVIF chứ không phải lỗi compile.

Cách làm phổ biến: handle trơn virtual riscv_if, rồi phân quyền bằng clocking block (vif.mon_cb chỉ có input, vif.drv_cb có output). Nếu bắt buộc dùng modport, chọn modport tại điểm set với một kiểu riêng được khai báo ở package (typedef virtual riscv_if.mon mon_vif_t;) và dùng đúng typedef đó cả ở set lẫn get.

#1step khác #1 thế nào? Khi nào dùng input #1step?

#1step là “bước thời gian nhỏ nhất của simulator” — tương đương lấy mẫu ở Preponed region của time-step hiện tại, bất kể timescale. #1 là 1 đơn vị timescale (1ns nếu `timescale 1ns/1ps): nếu DUT có delay combinational >1ns hoặc đổi timescale, giá trị lấy mẫu có thể sai.

Dùng default input #1step cho monitor (chỉ nhìn); với driver thường đặt default output #1 hoặc skew nhỏ để mô phỏng setup/hold thực tế.

Backdoor khác frontdoor ở điểm nào về mặt UVM? Nêu một rủi ro khi lạm dụng backdoor.

Frontdoor: đi qua giao thức thật (ở đây: chương trình LW/SW chạy trên pipeline) → kiểm cả datapath, tốn chu kỳ. Backdoor: đọc/ghi thẳng biến RTL qua hierarchical reference/DPI → 0 thời gian mô phỏng.

Rủi ro: backdoor bỏ qua logic thật nên có thể che lỗi (ví dụ nạp ROM bằng backdoor thì không bao giờ phát hiện lỗi fetch ở reset). Quy tắc: backdoor để setup nhanh và kiểm chéo, frontdoor để verify chức năng.

Vì sao đặt backdoor task trong interface thay vì trong driver/monitor?

(1) Tách trách nhiệm: đường dẫn RTL nằm ở một nơi — đổi DUT (Lab 15 sang riscv_avalon_wrapper) chỉ sửa interface, không sửa driver/scoreboard. (2) Tái dùng: nhiều component (driver nạp ROM, scoreboard sweep regfile, RAL backdoor) cùng gọi. (3) Interface là chỗ hợp lệ duy nhất để dùng hierarchical reference mà không làm class “biết” cấu trúc DUT.

Đánh đổi: interface gắn với DUT cụ thể → không tái dùng cho DUT khác. Giải pháp: lớp trừu tượng riscv_backdoor_if (virtual class) với 2 hiện thực.

Shadow pipeline/retire reconstruction nên viết ở top module hay trong monitor UVM? Tại sao?

Trong module (top/interface): logic đó là mạch tuần tự bám theo clock và net nội bộ của DUT — viết bằng always với reset rõ ràng, không cần phase/objection, và chạy từ time 0 (monitor class chỉ chạy sau run_phase start).

Monitor UVM chỉ nên đọc kết quả (cổng retire) và dựng transaction. Nhờ vậy khi có RTL đã có cổng RVFI thật, ta chỉ thay phần module, monitor giữ nguyên — đây là ý nghĩa của “ranh giới ổn định”.

Có nên đặt assertion trong interface không? So với bind?

Assertion trong interface hợp lý cho kiểm tra giao thức tại ranh giới (ví dụ ret_valid |-> !$isunknown(ret_pc)) và đi theo interface khi tái dùng VIP. Assertion về nội bộ DUT (forwarding, flush) dùng bind (Lab 8) để không phải sửa RTL. Điểm chung: cả hai đều là module-world; báo lỗi vào UVM cần cầu nối (Lab 8 §6).

13. Cheat-sheet

interface riscv_if(input logic clk);
  logic rst; logic ret_valid,ret_reg_write,ret_mem_write; logic[4:0] ret_rd;
  logic[31:0] ret_pc,ret_instr,ret_wb_data,ret_mem_addr,ret_mem_wdata;
  clocking ret_cb @(posedge clk); default input #1step; input ret_valid,...; endclocking
  modport mon(clocking ret_cb,...); modport drv(input clk, output rst);
  task automatic load_instr(int idx, logic[31:0] d); dut.u_imem.mem[idx]=d; endtask
  function automatic logic[31:0] peek_reg(int r); return r? dut.u_regfile.registers[r]:0; endfunction
endinterface
