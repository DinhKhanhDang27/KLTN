Tổng quan lab
  • Lab này làm gì: viết thư viện sequence — mỗi lớp lệnh một sequence (R-type, I-type ALU, Load/Store, Branch, Jump, Upper-imm). Tất cả kế thừa riscv_prog_base_seq: sinh thân chương trình (random lệnh hợp lệ, last_instr=0) rồi tự nối lệnh halt (jal x0,0, last_instr=1) để driver biết dừng nạp.
  • Tạo ra file nào: tb/seq/riscv_prog_base_seq.sv + 6 file sequence lớp lệnh, và 6 test con chọn từng sequence.
  • Nhận gì từ lab trước: toàn bộ khung Lab 5.
  • Lab sau dùng để làm gì: Lab 7 ghép nhiều sequence thành chương trình hỗn hợp qua virtual sequence; Lab 9+ ISS/scoreboard dùng các lệnh random này để tự kiểm.
Trọng tâm UVM của lab
  • Vòng đời sequence: pre_start → pre_body → body → post_body → post_start; start() có tham số gì.
  • start_item/finish_item bên trong: arbitration, grant, item_done; so với macro `uvm_do*.
  • Sequence là object: randomizable, kế thừa, tham số hóa; sequence library & uvm_sequence_library.
  • Sequence không biết DUT: nó chỉ sinh item; mọi thứ khác (timing, hazard) thuộc driver/DUT.
  • RISC-V: mỗi lớp lệnh một sequence; hazard sinh ra tự nhiên từ phụ thuộc register — không cấm.
Hazard pipeline & stimulus: vì có forwarding + load-use stall, các lệnh random phụ thuộc nhau (rd lệnh này = rs lệnh sau) là tốt — chúng kích thích forwarding/stall. Ta không cấm phụ thuộc; chỉ đảm bảo lệnh hợp lệ & địa chỉ bộ nhớ trong vùng.

3. Mục tiêu học

  • uvm_sequence + body() + start_item/finish_item (và macro `uvm_do_with).
  • Kế thừa sequence: base lo khung chương trình, con lo "sinh lệnh gì".
  • randomize() with {} ràng buộc inline theo lớp lệnh.
  • Tham số hóa sequence (số lệnh n) qua field rand.

6. Lý thuyết ngắn — sequence body & phân tách (+ UVM bên trong)

  1. start_item/finish_item: xin "khe" trên sequencer, randomize item, chốt gửi. Driver phía kia get_next_item.
  2. Base + con: base body() gọi gen_body() (con override) rồi gửi halt. Giảm lặp code.
  3. Halt terminator: đúng 1 item mang last_instr=1 — luôn là jal x0,0 cuối để driver dừng nạp & drain.
  4. Ràng buộc inline: with { op inside {ADD,SUB,...}; } giới hạn lớp lệnh mà không sửa constraint gốc trong item.

6.5. Vòng đời của một sequence

seq.start(sqr, parent_seq, priority, call_pre_post)
   ├─ pre_start()     ← luôn chạy
   ├─ pre_body()      ← khi call_pre_post=1 (mặc định của start())
   ├─ body()          ← bạn viết ở đây
   ├─ post_body()
   └─ post_start()

Ba điều dễ nhầm: (1) start() là task block — trả về khi body() xong; (2) pre_body/post_body chạy khi call_pre_post=1 (mặc định của start()) nhưng sequence con chạy bằng macro `uvm_do* được gọi với call_pre_post=0 nên không chạy chúng — đừng đặt logic bắt buộc ở đó; (3) sequence cần sequencer để chạy — start(null) hợp lệ chỉ cho sequence không gửi item (virtual sequence, Lab 7).

6.6. start_item / finish_item — điều gì xảy ra

  1. start_item(it): gửi yêu cầu arbitration tới sequencer, block tới khi được grant (có thể lâu nếu nhiều sequence cạnh tranh hoặc driver chưa sẵn sàng).
  2. Giữa hai lệnh bạn randomize/gán — đây là chỗ đúng để random hóa (late randomization: dữ liệu có thể phụ thuộc trạng thái lúc được grant).
  3. finish_item(it): đẩy item xuống driver, rồi block tới khi driver gọi item_done().

6.7. Pattern thư viện sequence

  • Base + hook: base lo khung (n lệnh + halt), con override gen_one() — template method pattern (bản lab).
  • Tham số qua rand field/config: rand int n + randomize() with {n==8;}; hoặc đọc cfg từ sequencer: uvm_config_db#(riscv_agent_config)::get(m_sequencer,"","cfg",cfg) (context là component — sequence không có hierarchy).
  • uvm_sequence_library: đăng ký nhiều sequence rồi tự chọn (UVM_SEQ_LIB_RAND/RANDC/ITEM) — cách nhanh có random-sequence-selection, cần `uvm_add_to_seq_lib.
  • Objection trong sequence gốc: UVM 1.2 hỗ trợ set_automatic_phase_objection(1) để sequence tự raise/drop theo starting_phase.
// Sequence cần đọc config: m_sequencer là sequencer đang chạy nó (kiểu uvm_sequencer_base)
riscv_agent_config cfg;
if (!uvm_config_db#(riscv_agent_config)::get(m_sequencer, "", "cfg", cfg))

Bẫy: p_sequencer (kiểu cụ thể, khai bằng `uvm_declare_p_sequencer) làm sequence gắn cứng vào một loại sequencer → khó tái dùng. Ưu tiên m_sequencer + config_db, hoặc truyền handle qua field; dùng p_sequencer khi bạn thật sự cần (virtual sequence, Lab 7).

7. Iteration 0 — base + R-type + I-type sequence

tb/seq/riscv_prog_base_seq.sv 
`ifndef RISCV_PROG_BASE_SEQ_SV
`define RISCV_PROG_BASE_SEQ_SV
// Khung chương trình: gen_body() (con override) + nối halt(jal x0,0, last=1)
class riscv_prog_base_seq extends uvm_sequence #(riscv_seq_item);
  `uvm_object_utils(riscv_prog_base_seq)
  // seq.start() KHÔNG tự randomize: không có giá trị khởi tạo thì n=0 → chương trình chỉ còn lệnh halt.
  // Mặc định 8 lệnh; muốn ngẫu nhiên trong c_n thì gọi seq.randomize() trước start (Iteration 1).
  rand int unsigned n = 8;         // số lệnh thân
  bit               append_halt = 1;   // Lab 7: vseq tắt cờ này ở sub-seq, chỉ seq cuối mới gửi halt
  constraint c_n { n inside {[1:10]}; }   // [1:10]: Lab 7 ép n==2/3 bằng randomize() with — c_n không được loại các giá trị đó
  function new(string name="riscv_prog_base_seq"); super.new(name); endfunction

  // Con override hàm này để sinh 1 lệnh thuộc lớp của mình.
  virtual task gen_one(output riscv_seq_item it);
    it = riscv_seq_item::type_id::create("it");
    start_item(it);
    assert(it.randomize());        // random hợp lệ toàn tập (mặc định)
    it.use_raw = 0; it.last_instr = 0;
    finish_item(it);
  endtask

  task body();
    riscv_seq_item it;
    repeat (n) gen_one(it);
    // halt
    if (append_halt) begin
      riscv_seq_item h = riscv_seq_item::type_id::create("halt");
      start_item(h); void'(h.randomize());
      h.use_raw = 1; h.raw_word = 32'h0000006f; h.last_instr = 1;   // jal x0,0
      finish_item(h);
    end
  endtask
endclass
`endif

`ifndef RISCV_LS_SEQ_SV
`define RISCV_LS_SEQ_SV
// Sinh cặp SW rồi LW cùng địa chỉ để có dữ liệu đọc ra hợp lý.
class riscv_ls_seq extends riscv_prog_base_seq;
  `uvm_object_utils(riscv_ls_seq)

    it = riscv_seq_item::type_id::create("it");

    assert(it.randomize() with {
      op inside {LW,SW};
      rs1 == 0;                 // base = x0 => địa chỉ = imm
      imm inside {[0:255]};

  endtask

8. Iterations

Iteration 1 — tham số hóa số lệnh qua randomize sequence

Trong test: seq.randomize() with { n == 8; } trước seq.start.

Khác biệt

Chương trình đúng 8 lệnh + halt. Dạy: sequence cũng là object randomize được.

Iteration 2 — dùng macro `uvm_do_with

Thay cụm create/start/randomize/finish bằng `uvm_do_with(it,{op inside{ADD,SUB};}).

Khác biệt

Gọn hơn nhưng khó chèn last_instr/use_raw (phải set trước finish). Dạy: macro tiện nhưng kém linh hoạt — nhiều team tránh.

Iteration 3 — ls_seq: tách SW trước LW cùng địa chỉ

Override gen_body: sinh cặp SW addr rồi LW addr (cùng imm).

Khác biệt

LW đọc đúng giá trị vừa SW → kiểm được đường dữ liệu bộ nhớ + load-use stall. Dạy: sequence có thể "kể chuyện" (store rồi load).

Iteration 4 — branch_seq nhảy lùi (vòng lặp ngắn, có giới hạn)

Thêm đếm để tránh lặp vô hạn; dùng beq với bộ đếm.

Khác biệt

Tạo luồng điều khiển thực; flush xảy ra nhiều. Dạy: stimulus cho đường rẽ nhánh (coverage Lab 12).

Iteration 5 — mixed: gọi 2 sequence nối tiếp trên cùng sequencer

Trong test: rtype.start(sqr); itype.start(sqr); — nhưng chỉ 1 được mang halt.

Khác biệt

Phải bỏ halt ở seq đầu (last_instr=0 toàn bộ) để 2 seq ghép thành 1 chương trình. Dẫn tới nhu cầu virtual sequence (Lab 7) điều phối nhiều seq gọn gàng.

12. Phỏng vấn — hỏi & đáp

Bấm câu hỏi để xem đáp án — nên tự trả lời miệng trước khi mở. Mỗi câu có ví dụ cụ thể như khi bị hỏi trong phỏng vấn.

start_item và finish_item mỗi cái block ở đâu? Vì sao nên random giữa hai lệnh đó?

start_item block tới khi sequencer cấp grant; finish_item block tới khi driver item_done. Random giữa hai lệnh gọi là late randomization: dữ liệu được sinh sau khi biết chắc item sẽ được gửi, nên có thể dựa vào trạng thái mới nhất (ví dụ biết register nào vừa ghi). Nếu randomize trước start_item mà sequencer đang bận lâu, dữ liệu có thể đã “lỗi thời” so với mô hình trạng thái.

start_item(it);
assert(it.randomize() with { op inside {LW,SW}; imm inside {[0:255]}; });   // random muộn
it.last_instr = 0;
finish_item(it);
`uvm_do_with` có lợi/hại gì? Bạn dùng macro hay viết tay?

Lợi: 1 dòng thay cho create/start/randomize/finish. Hại: (1) không chèn được bước giữa start và finish (gán last_instr), (2) ẩn kết quả randomize() (nó báo warning chứ không fatal), (3) macro nhiều tầng → debug và stack trace khó đọc, (4) with trong macro dễ dính bẫy scope. Trả lời tốt: “Dùng viết tay cho code chạy thật, macro chỉ cho test nhanh/legacy; kiểm tra randomize và dùng uvm_fatal.”

pre_body/post_body có luôn chạy không? Vì sao UVM chia 5 hàm như vậy?

Với seq.start(sqr) mặc định call_pre_post=1 nên pre_body/post_body có chạy. Chúng không chạy khi bạn truyền call_pre_post=0 hoặc khi sequence con được khởi chạy bằng macro `uvm_do* (macro gọi start(…, 0)). pre_start/post_start thì luôn chạy.

Hệ quả thực hành: logic bắt buộc (khởi tạo, xả hàng đợi) đặt ở đầu body() hoặc pre_start(), không phụ thuộc pre_body. Việc chia hàm để sequence cha “bọc” con: cha có pre_do/mid_do/post_do được gọi quanh mỗi item/sequence con của nó.

child.start(sqr, this);          // pre_start, pre_body, body, post_body, post_start
`uvm_do(child)                   // pre_start, body, post_start  (call_pre_post = 0)
Sequence có biết DUT, interface hay timing không? Cho ví dụ vi phạm.

Không và không nên: sequence chỉ sinh item (transaction). Vi phạm điển hình: sequence gọi @(posedge vif.clk) hay đọc vif — gắn cứng sequence vào interface cụ thể, không tái dùng được, dễ race. Thứ cần timing đặt trong driver/ config (cfg.delay); thứ cần trạng thái DUT lấy từ monitor/scoreboard qua event/analysis (reactive sequence).

p_sequencer vs m_sequencer khác nhau thế nào?

m_sequencer là con trỏ uvm_sequencer_base có sẵn (sequencer đang chạy sequence). p_sequencer là con trỏ đã ép sang kiểu cụ thể do `uvm_declare_p_sequencer(T) sinh ra (qua $cast trong m_set_p_sequencer). Dùng p_sequencer khi cần truy cập thành phần của sequencer cụ thể (handle sequencer con ở virtual sequencer); không dùng thì giữ m_sequencer để sequence tái dùng được trên nhiều sequencer.

Randomize chính sequence (rand int n) có ý nghĩa gì? Ví dụ.

Sequence là uvm_object nên có rand field và constraint như item. Dùng để điều khiển “hình dạng” kịch bản từ test mà không sửa sequence: seq.randomize() with { n == 8; }; hay để config-space random. Lưu ý: nếu n có constraint inside {[4:10]} thì with { n==0; } mâu thuẫn → randomize() trả 0; muốn n=0 phải gán trực tiếp (hseq.n = 0;) như Lab 7.

Sequence library là gì? Khi nào dùng thay vì viết vseq tay?

uvm_sequence_library chứa danh sách sequence; khi start nó tự chọn và chạy theo chế độ (UVM_SEQ_LIB_RAND, RANDC, ITEM, USER) selection_mode với số lần giữa min_random_count..max_random_count. Dùng khi cần stress ngẫu nhiên “bốc” trộn nhiều sequence; vseq viết tay hợp khi thứ tự có ý nghĩa (ví dụ cấu hình rồi mới kích hoạt). Với CPU: ghép lớp lệnh có thể random, nhưng halt phải luôn ở cuối — nên vseq tay hợp hơn.

Hai sequence cùng start trên một sequencer thì item của chúng được ghép thế nào?

Theo arbitration của sequencer (mặc định FIFO theo thời điểm start_item; có thể UVM_SEQ_ARB_STRICT_FIFO/WEIGHTED/RANDOM/USER). Item hai sequence có thể đan xen. Với chương trình CPU (thứ tự quyết định ngữ nghĩa), đan xen phá hỏng chương trình → dùng tuần tự trong virtual sequence, hoặc lock()/grab() để một sequence giữ sequencer (Lab 7).

13. Cheat-sheet

class riscv_prog_base_seq extends uvm_sequence#(riscv_seq_item);
  rand int unsigned n;  constraint{n inside{[4:10]};}
  virtual task gen_one(output riscv_seq_item it); /* random toàn tập */ endtask
  task body(); repeat(n) gen_one(it); /* append halt jal x0,0 last=1 */ endtask
// con: override gen_one với randomize() with { op inside {<lớp>}; }

14. Bài tập code & câu hỏi nâng cao UVM

8 bài rèn tay, tăng dần độ khó. Làm trên baseline của lab này; đáp án chỉ là hướng tham khảo — giá trị nằm ở việc bạn tự gõ, chạy và đọc log.

0 / 8 bài đã làm
★ Dễ

EX1 — Late randomization chứng minh

Trong gen_one, gán it.imm từ một biến cục bộ cập nhật mỗi lần (ví dụ addr_cnt += 4;) sau start_item. Rồi thử gán trước. Hai bản khác nhau thế nào khi hai sequence chạy đồng thời?
Gợi ý & đáp án tham khảo

Trước start_item: giá trị tính ở lúc yêu cầu; sau: lúc được grant. Nếu nhiều sequence tranh, bản sau phản ánh đúng thứ tự thực sự item đến driver.

★ Dễ

EX2 — Bỏ hẳn macro

Tìm mọi chỗ dùng `uvm_do* trong code của bạn (nếu có) và viết lại bằng start_item/finish_item, kiểm tra randomize(). Giải thích sự khác biệt về log khi randomize thất bại.
Gợi ý & đáp án tham khảo

`uvm_do_with khi randomize fail in UVM_WARNING rồi vẫn gửi item chưa hợp lệ; bản tay bạn quyết định uvm_fatal.

★★ Vừa

EX3 — Lifecycle log

Override pre_start, pre_body, body, post_body, post_start chỉ để in tên. Chạy ba cách: seq.start(sqr); child.start(sqr, parent_seq); `uvm_do(child) trong body() của parent. Lập bảng hàm nào chạy ở mỗi trường hợp.
Gợi ý & đáp án tham khảo

Cách 1 và 2: đủ 5 hàm (call_pre_post=1). Cách 3 (macro): chỉ pre_start → body → post_start. Ở cách 2 và 3, parent còn nhận pre_do/mid_do/post_do. Bảng này là câu hỏi phỏng vấn kinh điển.

★★ Vừa

EX4 — Đọc config trong sequence

Cho riscv_prog_base_seq đọc cfg.max_prog_len từ config object (qua m_sequencer) và n = min(n, cfg.max_prog_len). Test set max_prog_len=6.
Gợi ý & đáp án tham khảo

Dùng uvm_config_db#(riscv_agent_config)::get(m_sequencer, "", "cfg", cfg). Nhớ rằng agent đã set cfg cho "drv"/"mon" nhưng sequencer là component khác → cần set thêm cho "sqr".

★★ Vừa

EX5 — Sequence library

Tạo riscv_seq_lib extends uvm_sequence_library#(riscv_seq_item), thêm 4 sequence lớp lệnh bằng `uvm_add_to_seq_lib. Đặt selection_mode = UVM_SEQ_LIB_RANDC và min/max_random_count. Chạy và in thứ tự được chọn.
Gợi ý & đáp án tham khảo

Mỗi sequence vẫn tự nối halt → nhiều halt! Bạn sẽ thấy driver cắt chương trình — nhắc lại vì sao Lab 7 đưa cờ append_halt. Cách xử lý: thư viện chạy với append_halt=0, vseq thêm halt cuối.

★★ Vừa

EX6 — Branch lùi có giới hạn

Viết riscv_loop_seq: addi x1,x0,N; loop: addi x1,x1,-1; bne x1,x0,loop. Dùng imm=-4 cho BNE. Kiểm tra encode (B-type immediate âm) đúng bằng cách quan sát PC lặp.
Gợi ý & đáp án tham khảo

Ràng buộc imm inside {-4} trên bit [31:0] cần ép sign; viết imm == 32'hFFFFFFFC. Retire stream sẽ lặp cùng 2 PC N lần.

★★★ Khó

EX7 — Reactive sequence

Sequence nghe monitor: sau mỗi retire mà stall=1, chèn thêm 2 lệnh độc lập (để thấy stall giảm). Gợi ý: monitor phát event/analysis; sequence wait trên uvm_event lấy từ uvm_event_pool.
Gợi ý & đáp án tham khảo 
uvm_event ev = uvm_event_pool::get_global("retire_stall");
// monitor: ev.trigger(tr);     // sequence: ev.wait_trigger_data(data);

Chú ý: với driver nạp ROM theo lô (Lab 3), stimulus không phản ứng được với retire thật — bài tập này minh họa giới hạn của kiến trúc “nạp rồi chạy” và vì sao core có bus (Avalon) cần reactive sequence.

★★★ Khó

EX8 — So sánh bằng thống kê

Chạy riscv_rtype_seq 50 lần với 50 seed, thu histogram op từ monitor. Dùng uvm_report_server hoặc file CSV. Kiểm chứng toàn bộ 10 lệnh R-type đều xuất hiện ≥ 1 lần; nếu không, vì sao?
Gợi ý & đáp án tham khảo

Nếu có op không xuất hiện ở 50 seed thì kiểm tra constraint: op inside {…} kết hợp dist trong item (Lab 2) có thể làm xác suất nhỏ — đây là bài kiểm tra “coverage mong đợi vs thực tế”, mở đường cho Lab 12.
