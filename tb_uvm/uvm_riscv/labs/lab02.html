Tổng quan lab
  • Lab này làm gì: định nghĩa riscv_seq_item — một "giao dịch" = một lệnh RV32I. Có trường ngẫu nhiên (loại lệnh, rs1/rs2/rd, immediate), ràng buộc để lệnh hợp lệ và nằm trong tập core hỗ trợ, và hàm encode() ghép thành word 32-bit đúng 6 format (R/I/S/B/U/J).
  • Tạo ra file nào: tb/agent/riscv_seq_item.sv + top thử nghiệm nhỏ riscv_item_tb.sv (randomize vài item, in + nạp vào ROM để kiểm chứng encode).
  • Nhận gì từ lab trước: riscv_if.sv baseline (Lab 1).
  • Lab sau dùng để làm gì: Lab 3 driver lấy item này, gọi encode() rồi backdoor nạp ROM; Lab 9 ISS dùng chính các trường để dự đoán; Lab 12 coverage sample các trường.
Trọng tâm UVM của lab
  • uvm_sequence_item là uvm_object (không có phase, không có parent): vòng đời, type_id::create(name), và 5 “data method” copy/clone/compare/print/pack.
  • Field macros vs do_* thủ công — đánh đổi hiệu năng/độ kiểm soát mà phỏng vấn hay hỏi.
  • Constrained random: solver, solve…before, rand_mode/constraint_mode, inline with và bẫy local::, pre/post_randomize.
  • Polymorphism: virtual là điều kiện để factory override (Lab 14) thật sự đổi hành vi — đã sửa encode() thành virtual trong code của lab.
  • Encode 6 format RISC-V chỉ là “thân hàm” — phần UVM là cách item được thiết kế để tái dùng.

  riscv_seq_item r;
  if (!$cast(r, rhs)) return 0;
  return super.do_compare(rhs, comparer) && (op == r.op) && (rd == r.rd) && (rs1 == r.rs1) && (imm == r.imm);

6.3. Randomization — những điều solver làm thật sự

  • randomize() trả 0 khi mâu thuẫn ràng buộc; nếu bạn không kiểm tra, item giữ giá trị cũ và test “chạy” với stimulus sai. Luôn if (!it.randomize()) `uvm_fatal(...) hoặc assert.
  • rand (có lặp) vs randc (hoán vị tuần hoàn, mỗi giá trị 1 lần rồi mới lặp — chỉ ≤ 8 bit hợp lý).
  • dist: := gán trọng số cho từng giá trị; :/ chia trọng số cho cả khoảng.
  • solve a before b: đổi phân bố, không đổi tập nghiệm hợp lệ.
  • rand_mode(0) tắt random 1 biến; constraint_mode(0) tắt 1 constraint — cách “nới” constraint cho negative test mà không sửa class.
  • pre_randomize() chạy trước, post_randomize() chỉ chạy khi randomize thành công → nơi chốt trường dẫn xuất (opcode/funct).
Bẫy with: trong it.randomize() with { rd == rd; }, cả hai vế đều resolve vào field của it (luôn đúng!). Muốn so với biến cục bộ của sequence phải viết rd == local::rd;. Lỗi này khiến constraint “biến mất” mà không có cảnh báo.

6.4. Polymorphism & factory — vì sao virtual

Lab 14 sẽ override riscv_seq_item bằng riscv_illegal_item. Driver giữ handle kiểu riscv_seq_item; chỉ khi encode() là virtual thì lời gọi req.encode() mới đi vào bản của lớp con. Nếu quên virtual, override “có vẻ thành công” (đúng kiểu object trong print()) nhưng hành vi vẫn là của lớp cha — lỗi rất khó thấy.

6.5. Stimulus item vs observed item

riscv_seq_item mô tả ý định (op, rs, imm) và randomizable; riscv_retire_item (Lab 4) mô tả quan sát và không rand. Tách hai lớp giúp scoreboard so ý định ↔ thực tế, và monitor không kéo theo constraint thừa.

RISC-V recap: 6 format lệnh & opcode (bạn đã biết — mở nếu cần) 
R:  funct7[31:25] rs2[24:20] rs1[19:15] funct3[14:12] rd[11:7]  opcode[6:0]
I:  imm[31:20]              rs1[19:15] funct3[14:12] rd[11:7]  opcode   (shift: funct7+shamt)
S:  imm[31:25] rs2[24:20] rs1[19:15] funct3[14:12] imm[11:7]  opcode
B:  imm[12|10:5] rs2 rs1 funct3 imm[4:1|11] opcode
U:  imm[31:12]                          rd[11:7]  opcode
J:  imm[20|10:1|11|19:12]                rd[11:7]  opcode
Opcode tập hỗ trợ: R=0110011, I-ALU=0010011, LW=0000011(f3=010), SW=0100011(f3=010), Branch=1100011, JAL=1101111, JALR=1100111(f3=000), LUI=0110111, AUIPC=0010111.

7. Iteration 0 — item tối thiểu + encode R/I

Xem full code: tb/agent/riscv_seq_item.sv 
// tb/agent/riscv_seq_item.sv
`ifndef RISCV_SEQ_ITEM_SV
`define RISCV_SEQ_ITEM_SV

class riscv_seq_item extends uvm_sequence_item;

  // Tập lệnh được core hỗ trợ (19 lệnh).
  typedef enum {
    ADD, SUB, SLL, SLT, SLTU, XOR, SRL, SRA, OR, AND,           // R-type
    ADDI, SLTI, SLTIU, XORI, ORI, ANDI, SLLI, SRLI, SRAI,       // I-type ALU
    LW, SW, BEQ, BNE, BLT, BGE, BLTU, BGEU,                     // mem + branch
    JAL, JALR, LUI, AUIPC                                       // jump + upper imm
  } instr_e;

  rand instr_e      op;
  rand bit [4:0]    rs1, rs2, rd;
  rand bit [31:0]   imm;

  // Trường dẫn xuất (chốt ở post_randomize) — dùng khi encode/debug.
  bit [6:0] opcode, funct7;
  bit [2:0] funct3;

  `uvm_object_utils_begin(riscv_seq_item)
    `uvm_field_enum(instr_e, op, UVM_ALL_ON)
    `uvm_field_int(rs1, UVM_ALL_ON)
    `uvm_field_int(rs2, UVM_ALL_ON)
    `uvm_field_int(rd,  UVM_ALL_ON)
    `uvm_field_int(imm, UVM_ALL_ON)
  `uvm_object_utils_end

  function new(string name="riscv_seq_item"); super.new(name); endfunction

  // ---- Ràng buộc hợp lệ ----
  // Tránh ghi x0 vô ích cho lệnh có writeback (x0 bất biến) -> dễ quan sát.
  constraint c_rd_nonzero { if (op != SW && op != BEQ && op != BNE && op != BLT
                               && op != BGE && op != BLTU && op != BGEU) rd != 0; }
  // Shift chỉ dùng 5 bit shamt.
  // LƯU Ý xsim 2023.2: KHÔNG dùng `if (op inside {A,B,C}) ...` làm điều kiện trong constraint —
  // solver coi ràng buộc là vô điều kiện (randomize() ... with {op==JAL; imm==32'h800;} bị fail).
  // Viết điều kiện bằng so sánh `==` nối `||` thì đúng.
  constraint c_shamt { if (op == SLLI || op == SRLI || op == SRAI) imm inside {[0:31]}; }

  // ---- Chốt opcode/funct3/funct7 từ op ----
  function void post_randomize();
    opcode = 7'b0; funct3 = 3'b0; funct7 = 7'b0;
    case (op)
      ADD :begin opcode=7'b0110011; funct3=3'b000; funct7=7'b0000000; end
      SUB :begin opcode=7'b0110011; funct3=3'b000; funct7=7'b0100000; end
      SLL :begin opcode=7'b0110011; funct3=3'b001; end
      SLT :begin opcode=7'b0110011; funct3=3'b010; end
      SLTU:begin opcode=7'b0110011; funct3=3'b011; end
      XOR :begin opcode=7'b0110011; funct3=3'b100; end
      SRL :begin opcode=7'b0110011; funct3=3'b101; funct7=7'b0000000; end
      SRA :begin opcode=7'b0110011; funct3=3'b101; funct7=7'b0100000; end
      OR  :begin opcode=7'b0110011; funct3=3'b110; end
      AND :begin opcode=7'b0110011; funct3=3'b111; end
      ADDI :begin opcode=7'b0010011; funct3=3'b000; end
      SLTI :begin opcode=7'b0010011; funct3=3'b010; end
      SLTIU:begin opcode=7'b0010011; funct3=3'b011; end
      XORI :begin opcode=7'b0010011; funct3=3'b100; end
      ORI  :begin opcode=7'b0010011; funct3=3'b110; end
      ANDI :begin opcode=7'b0010011; funct3=3'b111; end
      SLLI :begin opcode=7'b0010011; funct3=3'b001; funct7=7'b0000000; end
      SRLI :begin opcode=7'b0010011; funct3=3'b101; funct7=7'b0000000; end
      SRAI :begin opcode=7'b0010011; funct3=3'b101; funct7=7'b0100000; end
      LW   :begin opcode=7'b0000011; funct3=3'b010; end
      SW   :begin opcode=7'b0100011; funct3=3'b010; end
      BEQ  :begin opcode=7'b1100011; funct3=3'b000; end
      BNE  :begin opcode=7'b1100011; funct3=3'b001; end
      BLT  :begin opcode=7'b1100011; funct3=3'b100; end
      BGE  :begin opcode=7'b1100011; funct3=3'b101; end
      BLTU :begin opcode=7'b1100011; funct3=3'b110; end
      BGEU :begin opcode=7'b1100011; funct3=3'b111; end
      JAL  :begin opcode=7'b1101111; end
      JALR :begin opcode=7'b1100111; funct3=3'b000; end
      LUI  :begin opcode=7'b0110111; end
      AUIPC:begin opcode=7'b0010111; end
    endcase
  endfunction

  // ---- Ghép 32-bit theo format ----
  // `virtual` là BẮT BUỘC: Lab 14 override item bằng factory; nếu encode() không virtual thì
  // handle kiểu riscv_seq_item vẫn gọi bản cơ sở → override không có tác dụng.
  virtual function bit [31:0] encode();
    bit [31:0] w; bit [11:0] i12; bit [4:0] shamt;
    i12   = imm[11:0];
    shamt = imm[4:0];
    unique case (op)
      // R-type
      ADD,SUB,SLL,SLT,SLTU,XOR,SRL,SRA,OR,AND:
        w = {funct7, rs2, rs1, funct3, rd, opcode};
      // I-type shift (shamt + funct7)
      SLLI,SRLI,SRAI:
        w = {funct7, shamt, rs1, funct3, rd, opcode};
      // I-type ALU + LW + JALR
      ADDI,SLTI,SLTIU,XORI,ORI,ANDI,LW,JALR:
        w = {i12, rs1, funct3, rd, opcode};
      // S-type (SW)
      SW:
        w = {i12[11:5], rs2, rs1, funct3, i12[4:0], opcode};
      // B-type
      BEQ,BNE,BLT,BGE,BLTU,BGEU:
        w = {imm[12], imm[10:5], rs2, rs1, funct3, imm[4:1], imm[11], opcode};
      // U-type
      LUI,AUIPC:
        w = {imm[31:12], rd, opcode};
      // J-type
      JAL:
        w = {imm[20], imm[10:1], imm[11], imm[19:12], rd, opcode};
      default: w = 32'h00000013; // NOP = addi x0,x0,0
    endcase
    return w;
  endfunction

  function string convert2str();
    return $sformatf("%s rd=x%0d rs1=x%0d rs2=x%0d imm=0x%0h -> 0x%08h",
                     op.name(), rd, rs1, rs2, imm, encode());
  endfunction

endclass
`endif

8. Iterations

Iteration 1 — thêm kiểm chứng SW/Branch

Thêm trong top: SW x5,8(x1) mong 0x0050A423 (nếu ra 0x00502423 là bạn đang encode SW x5,8(x0), rs1=x0); BEQ x1,x2,+8 mong 0x00208463.

Khác biệt

Xác nhận ghép bit S/B (phần đảo thứ tự immediate) đúng. Đây là chỗ hay sai nhất khi phỏng vấn.

Iteration 2 — phân bố dist thiên về ALU

Thêm constraint c_dist { op dist { [ADD:SRAI]:=8, LW:=2, SW:=2, [BEQ:BGEU]:=3, JAL:=1, JALR:=1, LUI:=2, AUIPC:=1 }; }. (Range là [ADD:SRAI], không phải [ADD:ANDI]: dải ANDI bỏ sót SLLI/SRLI/SRAI → trọng số 0 → Lab 6 itype_seq không sinh được shift.)

Kiểm chứng trên xsim 2023.2: khi op còn xuất hiện trong ràng buộc khác (ở đây c_rd_nonzero), xsim vẫn tôn trọng miền của dist nhưng bỏ qua trọng số → 400 lần randomize ra ~đều trên mọi lệnh (ALU chỉ ~30%, không phải ~85%). Dist đứng một mình thì đúng. Muốn phân bố thật sự lệch, bốc op có trọng số ở pre_randomize rồi ép (bản dưới đã chạy được: ALU ≈ 82%).
Full phần thêm vào riscv_seq_item (bản trọng số chắc chắn) 
  // Iteration 2: thiên về ALU. Trọng số `dist` bị xsim 2023.2 BỎ QUA khi op còn dính ràng buộc khác
  // (ở đây c_rd_nonzero) -> ra phân bố đều. Cách chắc chắn: bốc op có trọng số trong pre_randomize
  // rồi ép bằng ràng buộc; tắt bằng use_dist=0 khi sequence tự `with { op ... }`.
  bit       use_dist = 1;
  instr_e   pick;                       // KHÔNG rand: solver coi là hằng
  constraint c_pick { if (use_dist) op == pick; }
  function void pre_randomize();
    int unsigned r = $urandom_range(0, 178);          // tổng trọng số = 179
    if      (r < 152) pick = instr_e'(ADD + (r / 8)); // ADD..SRAI: 19 lệnh x 8
    else if (r < 154) pick = LW;
    else if (r < 156) pick = SW;
    else if (r < 174) pick = instr_e'(BEQ + ((r - 156) / 3)); // 6 branch x 3
    else if (r < 175) pick = JAL;
    else if (r < 176) pick = JALR;
    else if (r < 178) pick = LUI;
    else              pick = AUIPC;
  endfunction
Khác biệt

Phần lớn item là ALU; lệnh hiếm (JAL/JALR) vẫn xuất hiện. Dạy điều khiển phân bố stimulus — quan trọng cho coverage Lab 12. Khi sequence cần ràng buộc op riêng (randomize() with { op==...; }) hãy đặt use_dist=0 trước, nếu không c_pick sẽ xung đột.

Iteration 3 — ràng buộc imm theo loại lệnh

Thêm: load/store dùng imm nhỏ, căn chỉnh 4: if(op == LW || op == SW) imm inside {[0:255]}; if(op == LW || op == SW) imm[1:0]==0; (dùng ==/||, không dùng if(op inside{...}) — xsim 2023.2 xử lý sai, xem chú thích ở c_shamt).

Khác biệt

Địa chỉ data mem nằm trong 2048 byte và căn chỉnh word (DUT chỉ hỗ trợ word). Tránh sinh địa chỉ ngoài vùng.

Iteration 4 — cho phép rd=x0 ở 10% (để test x0 bất biến)

Nới c_rd_nonzero thành dist: rd dist {0:=1, [1:31]:=9}; (bỏ constraint cũ). Trên xsim 2023.2 dist này không cho 10% (đo 1000 lần: chỉ ~2 lần rd=0 vì trọng số bị bỏ qua — cùng lỗi như Iteration 2), nên dùng bản bốc ở pre_randomize (đo được 100/1000):

Full phần thay c_rd_nonzero 
  bit [4:0] rd_pick;                    // KHÔNG rand: solver coi là hằng
  constraint c_rd0 { rd == rd_pick; }   // thay c_rd_nonzero (bỏ constraint cũ)
  function void pre_randomize();
    rd_pick = ($urandom_range(0, 9) == 0) ? 5'd0 : 5'($urandom_range(1, 31));   // 10% x0
  endfunction
Khác biệt

Thỉnh thoảng rd=x0 → Lab 8 SVA và Lab 11 scoreboard phải thấy x0 vẫn =0 dù reg_write=1. Tạo stimulus cho test âm.

12. Phỏng vấn — hỏi & đáp

Bấm câu hỏi để xem đáp án — nên tự trả lời miệng trước khi mở. Mỗi câu có ví dụ cụ thể như khi bị hỏi trong phỏng vấn.

uvm_object khác uvm_component ở những điểm nào? Vì sao item không phải component?

Component có parent/hierarchy và phase; object thì không. Item được tạo/hủy mỗi giao dịch (hàng nghìn–triệu lần) nên cần nhẹ, không phải gắn vào cây và không tham gia phase. Dấu hiệu nhận biết trong code: constructor new(string name) (object) vs new(string name, uvm_component parent) (component); macro uvm_object_utils vs uvm_component_utils.

riscv_seq_item it = riscv_seq_item::type_id::create("it");     // object: 1 tham số
riscv_driver   d  = riscv_driver::type_id::create("drv", this); // component: có parent
type_id::create() khác new() thế nào? Cho ví dụ override thành công và thất bại.

create() hỏi factory “đang có override nào cho kiểu này không?” rồi trả đối tượng đúng kiểu; new() bỏ qua factory.

set_type_override_by_type(riscv_seq_item::get_type(), riscv_illegal_item::get_type());
a = riscv_seq_item::type_id::create("a");   // → thực chất là riscv_illegal_item  ✔
b = new("b");                               // → riscv_seq_item, override KHÔNG áp dụng  ✘

Một điều kiện nữa: lớp con phải đăng ký với factory (`uvm_object_utils) và được biên dịch trong package.

Ưu/nhược điểm của field macros? Bạn dùng gì ở dự án thật?

Ưu: nhanh để viết, tự có print/copy/compare/pack. Nhược: chậm khi chạy lượng lớn transaction, khó kiểm soát (không bỏ qua field, không so có điều kiện), thông điệp mismatch kém, hành vi đổi theo flag (UVM_NOCOMPARE…) dễ nhầm.

Thực tế: item “quan sát” (monitor) hay dùng field macros để print nhanh khi debug; item dùng trong scoreboard hiệu năng cao viết tay do_compare/do_copy/do_print và convert2str(). Trả lời tốt nên nêu được vì sao, kèm đoạn do_compare ngắn.

randomize() trả về 0 — bạn debug thế nào?

Nguyên nhân thường: ràng buộc mâu thuẫn (kể cả từ with inline), rand_mode(0) làm biến thành hằng gây xung đột, tràn bit.

if (!it.randomize() with { rd == 0; })    // class có: constraint c_rd_nonzero { rd != 0; }
  `uvm_fatal("RAND", $sformatf("randomize fail: %s", it.convert2str()))

Cách điều tra: (1) bật log solver của tool (xsim: -debug_solver/báo conflict), (2) tắt từng constraint bằng constraint_mode(0) để thu hẹp, (3) đơn giản hóa with, (4) kiểm tra rand_mode. Luôn kiểm tra giá trị trả về — bản lab dùng assert(it.randomize()).

dist với := và :/ khác nhau thế nào? Cho số liệu. 
x dist { 0 := 1, [1:3] := 1 };   // 0,1,2,3 mỗi giá trị trọng số 1 → mỗi giá trị 25%
x dist { 0 := 1, [1:3] :/ 1 };   // khoảng [1:3] CHIA 1 → mỗi giá trị 1/3 → 0 là 50%, 1/2/3 mỗi cái ~16.7%

Trong lab: op dist { [ADD:ANDI] := 8, LW := 2, … } dùng := trên khoảng enum → mỗi lệnh trong khoảng được 8 → ALU áp đảo. Nếu chủ ý “cả nhóm ALU chiếm 8 phần” thì phải dùng :/.

Giải thích local:: trong inline constraint với ví dụ. 
// trong sequence có biến cục bộ  int rd = 5;
it.randomize() with { rd == rd; };          // luôn đúng: cả hai là it.rd → KHÔNG ràng buộc gì
it.randomize() with { rd == local::rd; };   // đúng: it.rd == 5 (biến cục bộ của sequence)

Quy tắc: trong with, tên được tra cứu trong scope của đối tượng được randomize trước; muốn dùng biến bên ngoài phải qualify bằng local::.

pre_randomize/post_randomize dùng để làm gì? Khi nào post_randomize không chạy?

post_randomize chốt trường dẫn xuất (opcode/funct3/funct7 từ op) và có thể kiểm tra sanity; pre_randomize chuẩn bị (ví dụ bật/tắt rand_mode). post_randomize không chạy khi randomize() thất bại — nên item mang giá trị dẫn xuất cũ/rác: một lý do nữa phải kiểm tra giá trị trả về.

Lab này minh họa: bỏ post_randomize (Iteration 6) → opcode=0 → encode() ra word rác.

copy, clone và gán handle khác nhau thế nào? Vì sao monitor phải tạo item mới cho mỗi lần write()?

Gán handle (b = a) chỉ sao chép con trỏ — hai biến cùng một object. b.copy(a) sao chép nội dung vào object b đã có. b = a.clone() tạo object mới rồi copy (trả uvm_object, cần $cast).

Analysis port không sao chép — subscriber nhận cùng handle. Nếu monitor tái dùng một item rồi sửa tiếp, subscriber lưu handle (scoreboard queue) sẽ thấy dữ liệu đổi ngầm. Vì thế monitor create item mới mỗi giao dịch (hoặc subscriber phải clone() khi cần giữ).

13. Cheat-sheet

class riscv_seq_item extends uvm_sequence_item;
  rand instr_e op; rand bit[4:0] rs1,rs2,rd; rand bit[31:0] imm;
  function void post_randomize(); // chốt opcode/funct3/funct7 theo op
  virtual function bit[31:0] encode(); // R:{f7,rs2,rs1,f3,rd,op}  I:{imm12,rs1,f3,rd,op}
    //  S:{imm[11:5],rs2,rs1,f3,imm[4:0],op}  B:{imm[12],imm[10:5],rs2,rs1,f3,imm[4:1],imm[11],op}
    //  U:{imm[31:12],rd,op}  J:{imm[20],imm[10:1],imm[11],imm[19:12],rd,op}

14. Bài tập code & câu hỏi nâng cao UVM

8 bài rèn tay, tăng dần độ khó. Làm trên baseline của lab này; đáp án chỉ là hướng tham khảo — giá trị nằm ở việc bạn tự gõ, chạy và đọc log.

0 / 8 bài đã làm
★ Dễ

EX1 — Kiểm tra giá trị trả về

Sửa riscv_item_tb: bọc mọi randomize() bằng if (!…) `uvm_fatal. Thêm một with { rd == 0; op == ADD; } (mâu thuẫn c_rd_nonzero) và xem fatal có ra không.
Gợi ý & đáp án tham khảo

Bạn sẽ thấy UVM_FATAL … randomize fail. Nếu chỉ dùng void'(it.randomize()) thì không thấy gì — item giữ giá trị cũ. Đây là lỗi im lặng nguy hiểm nhất của constrained random.

★ Dễ

EX2 — Histogram phân bố

Randomize 2000 item, đếm số lần mỗi op trong mảng associative int hist[string], in ra. So khi dùng := và :/ trên khoảng [ADD:ANDI].
Gợi ý & đáp án tham khảo 
int hist[string];
repeat (2000) begin assert(it.randomize()); hist[it.op.name()]++; end
foreach (hist[k]) `uvm_info("HIST", $sformatf("%-6s %0d", k, hist[k]), UVM_LOW)
★★ Vừa

EX3 — Viết tay do_compare / do_copy / do_print

Bỏ field macros, hiện thực do_copy/do_compare/do_print. do_compare bỏ qua rs2 khi op là I-type. Viết test: hai item khác rs2 nhưng cùng ADDI phải so bằng nhau.
Gợi ý & đáp án tham khảo

Dùng comparer.compare_field_int("rd", rd, r.rd, 5) để mismatch hiện đúng trong report; hoặc trả bit thuần như ví dụ §6.2. Nhớ gọi super.do_compare.

★★ Vừa

EX4 — constraint_mode & rand_mode

Viết test directed: tắt c_rd_nonzero bằng it.c_rd_nonzero.constraint_mode(0) rồi ép rd==0; riêng imm dùng it.imm.rand_mode(0); it.imm = 32'h7ff;. Giải thích khác biệt giữa hai hàm.
Gợi ý & đáp án tham khảo

constraint_mode bật/tắt một ràng buộc theo tên; rand_mode bật/tắt một biến (biến thành state variable, solver coi là hằng). Cả hai đều “nới” item không cần sửa class — công cụ cho negative test.

★★ Vừa

EX5 — Bẫy local::

Trong một sequence thử: int rd = 7; it.randomize() with { rd == rd; }; rồi sửa thành local::rd. In it.rd qua 20 lần chạy mỗi bản.
Gợi ý & đáp án tham khảo

Bản đầu: rd ngẫu nhiên (constraint vô nghĩa). Bản sau: luôn 7 — nhưng nếu c_rd_nonzero vẫn bật và bạn đặt local::rd = 0 thì randomize() trả 0.

★★ Vừa

EX6 — solve … before và độ lệch phân bố

Thêm biến rand bit big; và constraint big -> imm > 1000;. Chạy 5000 lần, đếm big trước và sau khi thêm solve big before imm;.
Gợi ý & đáp án tham khảo

Không có solve before, big=1 chiếm tỷ lệ ~ theo số nghiệm của imm (thường >99%). Với solve big before imm ~50/50. Chú ý: không đổi tập nghiệm, chỉ đổi phân bố.

★★★ Khó

EX7 — Pack/unpack và so sánh bằng bitstream

Dùng pack_ints()/unpack_ints() (hoặc pack_bytes) để serialize item rồi dựng lại. Kiểm chứng it2.compare(it). Thảo luận khi nào pack hữu ích (DPI-C, file trace).
Gợi ý & đáp án tham khảo 
int unsigned bits[];  void'(it.pack_ints(bits));
riscv_seq_item it2 = riscv_seq_item::type_id::create("it2");
void'(it2.unpack_ints(bits));  assert(it.compare(it2));

Lưu ý: field nào không có flag UVM_PACK sẽ không được serialize.

★★★ Khó

EX8 — Bắt lỗi “virtual” bằng test

Cố ý bỏ virtual khỏi encode(). Viết riscv_illegal_item override encode() trả 32'h0000000b. Dùng factory override rồi gọi qua handle kiểu cha. Chứng minh override không có tác dụng, rồi sửa lại.
Gợi ý & đáp án tham khảo

Dùng `uvm_info("T", $sformatf("type=%s enc=%08h", it.get_type_name(), it.encode()), UVM_LOW): get_type_name() (virtual, đã có sẵn) sẽ báo riscv_illegal_item nhưng encode() không đổi → minh chứng sự khác biệt giữa “đúng kiểu” và “đúng hành vi”.
