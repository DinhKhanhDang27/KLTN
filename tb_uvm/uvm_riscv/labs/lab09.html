Tổng quan lab
  • Lab này làm gì: xây riscv_ref_model — một ISS (Instruction Set Simulator) mô phỏng RV32I theo đặc tả: giữ regfile + data memory + PC riêng, hàm step() giải mã + thực thi 1 lệnh và trả về một retire kỳ vọng (giống hệt riscv_retire_item). Đây là "golden" để scoreboard (Lab 10) đối chiếu.
  • Tạo ra file nào: tb/ref/riscv_ref_model.sv + top kiểm chứng riscv_iss_tb.sv (chạy standalone, so với tính tay).
  • Nhận gì từ lab trước: riscv_retire_item (Lab 4), seq_item (Lab 2).
  • Lab sau dùng để làm gì: Lab 10 nối ISS vào scoreboard so với DUT; Lab 11 so cả regfile/mem; Lab 13 ISS dự đoán truy cập bộ nhớ.
Trọng tâm UVM của lab
  • Reference model trong kiến trúc UVM: object trong scoreboard, component predictor, hay DPI-C — và đánh đổi từng cách.
  • Predictor pattern: model nhận gì (stimulus hay observed?) → độc lập golden và khả năng bắt lỗi.
  • Model là uvm_object + factory: override model bằng bản “có lỗi” để kiểm chứng scoreboard (mutation).
  • Đồng bộ trạng thái: reset, checkpoint, copy/clone.
  • Decode/execute RV32I là phần bạn đã biết — gấp vào mục recap; trọng tâm là nơi đặt và cách nối model.
Golden phải khớp ĐẶC TẢ, không copy RTL: ISS mô phỏng ý nghĩa ISA (theo tài liệu RV32I + tập lệnh core hỗ trợ), không sao chép logic RTL. Nếu RTL sai mà ISS cũng sao chép cái sai thì scoreboard "mù". Ở đây ISS viết độc lập từ semantics; nó không cần biết pipeline/hazard — chỉ chạy tuần tự từng lệnh.

6.2. Model nhận gì làm đầu vào? — câu hỏi kiến trúc quan trọng nhất

Có hai hướng, đánh đổi trái ngược:

  • Stimulus-driven: model nạp chương trình đã gửi (từ driver/sequence) và tự chạy; scoreboard so retire DUT ↔ dự đoán. Ưu: độc lập — bắt cả lỗi “DUT fetch sai lệnh”. Nhược: model phải tự quản control flow/timing.
  • Observation-driven (lab này): model được “lái” bằng chính retire của DUT (exec(act.pc, act.instr)). Ưu: đơn giản, không cần ảnh chương trình. Nhược: tin DUT về pc/instr — nếu DUT fetch nhầm lệnh, model thực thi đúng lệnh nhầm đó và scoreboard vẫn khớp.
Lỗ hổng cần biết: kiểm tra act.instr ↔ lệnh đã nạp (từ stimulus) ở scoreboard để vá lỗ hổng này. Đây là bài tập EX5. Thực tế dự án: dùng cả hai (stimulus-driven cho chương trình + observation cho từng retire).

6.3. Model như uvm_object: lợi ích của factory

Vì riscv_ref_model kế thừa uvm_object và tạo bằng type_id::create, bạn có thể override bằng một bản có lỗi cố ý (riscv_ref_model_buggy — SRA thành SRL) để kiểm chứng scoreboard thật sự bắt được lỗi — mutation testing cho chính môi trường verify:

// test negative: model bị hỏng → scoreboard PHẢI fail
set_type_override_by_type(riscv_ref_model::get_type(), riscv_ref_model_buggy::get_type());

6.4. Quản lý state: reset, checkpoint, copy

  • Reset: reset() khi DUT reset; quên reset → model mang state chương trình trước (lỗi ngầm khi chạy nhiều chương trình).
  • Checkpoint: clone()/copy() để lưu trạng thái trước nhánh dự đoán — hữu ích khi so khoảng retire không theo thứ tự (core OoO).
  • Associative array cho memory: byte dmem[int] thưa, đọc địa chỉ chưa ghi trả 0 (và cảnh báo nếu dùng exists) — quyết định rõ: coi “chưa ghi” là 0 hay không xác định?
RISC-V recap: fetch/decode/execute/writeback, little-endian (bạn đã biết — mở nếu cần)
  1. Fetch: instr = imem[pc>>2]. Decode: tách opcode/rd/ funct3/rs1/rs2/funct7 + sinh immediate theo format.
  2. Execute: tính kết quả ALU / địa chỉ / điều kiện rẽ nhánh / địa chỉ nhảy.
  3. Writeback & next PC: ghi xreg (bỏ x0), cập nhật pc (tuần tự hoặc nhảy), trả retire.
  4. Little-endian word: LW/SW đọc/ghi 4 byte; dmem lưu theo byte.

7. Iteration 0 — ISS đủ 19 lệnh

tb/ref/riscv_ref_model.sv 
// tb/ref/riscv_ref_model.sv — ISS RV32I golden (subset core hỗ trợ)
`ifndef RISCV_REF_MODEL_SV
`define RISCV_REF_MODEL_SV
class riscv_ref_model extends uvm_object;
  `uvm_object_utils(riscv_ref_model)

  bit [31:0] xreg [0:31];
  bit [31:0] imem [int];       // word-indexed (addr>>2)
  byte       dmem [int];       // byte-addressed
  bit [31:0] pc;

  function new(string name="riscv_ref_model"); super.new(name); reset(); endfunction

  function void reset();
    foreach (xreg[i]) xreg[i] = 0;
    pc = 0;
  endfunction

  function void load_word(int widx, bit [31:0] data); imem[widx] = data; endfunction

  // ---- helper đọc/ghi reg (x0 bất biến) ----
  function bit [31:0] rf(int r);  return (r==0) ? 32'd0 : xreg[r]; endfunction
  function void wf(int r, bit [31:0] v); if (r!=0) xreg[r] = v; endfunction

  // ---- ALU theo semantics (khớp alu.sv) ----
  function bit [31:0] alu(bit [3:0] op, bit [31:0] a, bit [31:0] b);
    case (op)
      4'b0000: return a & b;
      4'b0001: return a | b;
      4'b0010: return a + b;
      4'b0110: return a - b;
      4'b0011: return a ^ b;
      4'b0100: return a << b[4:0];
      4'b0101: return a >> b[4:0];
      4'b0111: return $signed(a) >>> b[4:0];
      4'b1000: return ($signed(a) < $signed(b)) ? 32'd1 : 32'd0;
      4'b1001: return (a < b) ? 32'd1 : 32'd0;
      default: return 32'd0;
    endcase
  endfunction

  function bit [31:0] ld_w(int addr);
    int b = addr & ~3;
    return {dmem[b+3], dmem[b+2], dmem[b+1], dmem[b]};
  endfunction
  function void st_w(int addr, bit [31:0] v);
    int b = addr & ~3;
    dmem[b]=v[7:0]; dmem[b+1]=v[15:8]; dmem[b+2]=v[23:16]; dmem[b+3]=v[31:24];
  endfunction

  // ---- step: thực thi 1 lệnh tại pc, trả retire kỳ vọng ----
  function riscv_retire_item step();
    riscv_retire_item rt = riscv_retire_item::type_id::create("exp");
    bit [31:0] w   = imem.exists(pc>>2) ? imem[pc>>2] : 32'h00000013; // NOP nếu trống
    bit [6:0]  opc = w[6:0];
    bit [4:0]  rd  = w[11:7], rs1 = w[19:15], rs2 = w[24:20];
    bit [2:0]  f3  = w[14:12];
    bit [6:0]  f7  = w[31:25];
    bit [31:0] immI = {{20{w[31]}}, w[31:20]};
    bit [31:0] immS = {{20{w[31]}}, w[31:25], w[11:7]};
    bit [31:0] immB = {{19{w[31]}}, w[31], w[7], w[30:25], w[11:8], 1'b0};
    bit [31:0] immU = {w[31:12], 12'b0};
    bit [31:0] immJ = {{11{w[31]}}, w[31], w[19:12], w[20], w[30:21], 1'b0};
    bit [31:0] a = rf(rs1), b = rf(rs2);
    bit [31:0] res, addr, nextpc;
    bit        taken;

    rt.pc = pc; rt.instr = w;
    rt.reg_write = 0; rt.rd = rd; rt.wb_data = 0;
    rt.mem_write = 0; rt.mem_addr = 0; rt.mem_wdata = 0;
    nextpc = pc + 4;

    case (opc)
      7'b0110011: begin // R-type
        bit [3:0] aop;
        case (f3)
          3'b000: aop = f7[5] ? 4'b0110 : 4'b0010; // sub/add
          3'b001: aop = 4'b0100; 3'b010: aop = 4'b1000; 3'b011: aop = 4'b1001;
          3'b100: aop = 4'b0011; 3'b101: aop = f7[5] ? 4'b0111 : 4'b0101;
          3'b110: aop = 4'b0001; 3'b111: aop = 4'b0000; default: aop=4'b0010;
        endcase
        res = alu(aop, a, b); rt.reg_write=1; rt.wb_data=res; wf(rd,res);
      end
      7'b0010011: begin // I-ALU
        bit [3:0] aop; bit [31:0] bop;
        case (f3)
          3'b000: begin aop=4'b0010; bop=immI; end // addi
          3'b010: begin aop=4'b1000; bop=immI; end // slti
          3'b011: begin aop=4'b1001; bop=immI; end // sltiu
          3'b100: begin aop=4'b0011; bop=immI; end // xori
          3'b110: begin aop=4'b0001; bop=immI; end // ori
          3'b111: begin aop=4'b0000; bop=immI; end // andi
          3'b001: begin aop=4'b0100; bop={27'd0,w[24:20]}; end // slli shamt
          3'b101: begin aop=f7[5]?4'b0111:4'b0101; bop={27'd0,w[24:20]}; end // srai/srli
          default:begin aop=4'b0010; bop=immI; end
        endcase
        res = alu(aop, a, bop); rt.reg_write=1; rt.wb_data=res; wf(rd,res);
      end
      7'b0000011: begin // LW
        addr = a + immI; res = ld_w(addr);
        rt.reg_write=1; rt.wb_data=res; wf(rd,res);
      end
      7'b0100011: begin // SW
        addr = a + immS; st_w(addr, b);
        rt.mem_write=1; rt.mem_addr=addr; rt.mem_wdata=b;
      end
      7'b1100011: begin // Branch
        case (f3)
          3'b000: taken = (a==b);                         // beq
          3'b001: taken = (a!=b);                         // bne
          3'b100: taken = ($signed(a) < $signed(b));      // blt
          3'b101: taken = ($signed(a) >= $signed(b));     // bge
          3'b110: taken = (a < b);                        // bltu
          3'b111: taken = (a >= b);                       // bgeu
          default: taken = 0;
        endcase
        if (taken) nextpc = pc + immB;
      end
      7'b1101111: begin // JAL
        rt.reg_write=1; rt.wb_data=pc+4; wf(rd, pc+4); nextpc = pc + immJ;
      end
      7'b1100111: begin // JALR
        rt.reg_write=1; rt.wb_data=pc+4; wf(rd, pc+4);
        nextpc = (a + immI) & ~32'd1;
      end
      7'b0110111: begin // LUI
        rt.reg_write=1; rt.wb_data=immU; wf(rd, immU);
      end
      7'b0010111: begin // AUIPC
        rt.reg_write=1; rt.wb_data=pc+immU; wf(rd, pc+immU);
      end
      default: ; // NOP / không hỗ trợ
    endcase

    pc = nextpc;
    return rt;
  endfunction
endclass
`endif

8. Iterations

Iteration 1 — thêm kiểm SRA vs SRL (dấu)

Thêm lui x5,0xFFFFF; srai x6,x5,4 và so kết quả có dấu.

Khác biệt

SRAI giữ dấu (>>>), SRLI không. Dạy: điểm sai kinh điển — nhầm toán tử dịch.

Iteration 2 — branch taken/not: beq bằng và khác

Chương trình có beq x1,x1,+8 (taken) và beq x1,x2,+8 (not taken).

Khác biệt

PC ISS nhảy/không đúng như semantics. Dạy: ISS tự quyết luồng điều khiển (độc lập DUT).

Iteration 3 — JALR xóa bit0

addi x1,x0,7; jalr x0,x1,0 → đích = 7 & ~1 = 6.

Khác biệt

ISS (a+imm)&~1 khớp RTL. Dạy: bẫy LSB của JALR.

Iteration 4 — AUIPC phụ thuộc PC

auipc x5,0 tại pc=8 → x5=8.

Khác biệt

AUIPC = pc+immU; ISS phải dùng pc hiện tại. Dạy: lệnh phụ thuộc PC.

Iteration 5 — cố ý sai: dùng immI cho SW

Đổi addr = a + immS → a + immI cho SW.

Khác biệt

Địa chỉ store sai khi imm có bit[11:5]≠0. Dạy: immediate đúng format là sống còn; Lab 10 sẽ lộ ngay qua mismatch.

12. Phỏng vấn — hỏi & đáp

Bấm câu hỏi để xem đáp án — nên tự trả lời miệng trước khi mở. Mỗi câu có ví dụ cụ thể như khi bị hỏi trong phỏng vấn.

Reference model đặt ở đâu trong UVM: trong scoreboard hay component riêng? Quyết định thế nào?

Model hàm thuần (không state theo thời gian, gọi đồng bộ) ⇒ uvm_object trong scoreboard, gọi step()/exec() trong write(). Model có state/timing hoặc cần chia sẻ expected cho nhiều checker (SB, coverage) ⇒ uvm_component predictor: nhận stimulus qua analysis_imp, phát expected qua analysis_port. Tiêu chí: ai cần expected? một nơi → object; nhiều nơi → component.

Vì sao golden model không được sao chép logic RTL? Cho ví dụ cụ thể của lab.

Nếu cùng một hiểu lầm đặc tả được đưa vào cả RTL và model, hai bên khớp nhau và scoreboard không bao giờ fail — verify vô nghĩa. Ví dụ: JALR chỉ xóa bit0 trong RTL; model viết độc lập theo spec (rs1+imm)&~1 khớp cả hai — nhưng nếu RTL sai (quên xóa bit0) thì model độc lập sẽ khác và lộ ra. Nguyên tắc: viết model từ spec/ISA manual, không đọc RTL; review bởi người khác.

Model “observation-driven” có điểm yếu gì? Khắc phục ra sao?

Model thực thi đúng lệnh DUT báo đã retire nên tin tưởng act.pc/act.instr. Nếu DUT fetch nhầm lệnh (ROM đọc sai địa chỉ), model chạy đúng lệnh nhầm và scoreboard khớp — lỗi bị che. Khắc phục: nạp chương trình thật (từ driver) vào model và kiểm act.instr == model.imem[act.pc] trước khi exec; hoặc stimulus-driven hoàn toàn.

if (iss.imem.exists(act.pc>>2) && iss.imem[act.pc>>2] !== act.instr)

Model là uvm_object hay component — hệ quả đối với factory/config?

Object: tạo bằng create(name) (không parent), không có phase, không nằm trong cây ⇒ không nhận config theo hierarchy (phải truyền handle/ cfg tường minh), nhưng override bằng factory vẫn hoạt động. Component: có phase, nhận config theo scope, hiện trong print_topology. Với model nhỏ, chọn object là hợp lý; nếu cần run_phase (mô phỏng timing) thì component.

Làm sao chứng minh scoreboard + model “thực sự bắt được lỗi” chứ không phải luôn pass?

Mutation: (1) bơm lỗi vào RTL (sửa ALU +1) và xác nhận FAIL; (2) hoặc override model bằng bản lỗi qua factory — nhanh hơn vì không sửa RTL; (3) kiểm tra từng nhóm so sánh có “tay” nào im lặng không (REG, MEM, CF). Quy tắc: một checker chưa từng thấy fail là một checker chưa được tin.

Xử lý reset giữa các chương trình với model như thế nào?

Model có hàm reset() (xóa xreg, pc=0; tùy trường hợp xóa dmem/imem). Scoreboard gọi reset() khi nhận sự kiện reset (analysis riêng/ uvm_event / cờ từ monitor). Không đồng bộ ⇒ model mang xreg chương trình trước ⇒ mismatch giả ở chương trình sau — nhận dạng bằng việc lỗi chỉ xuất hiện từ chương trình thứ hai trở đi.

Bộ nhớ model dùng byte dmem[int]: đọc địa chỉ chưa ghi trả gì? Có vấn đề không?

Associative array: đọc khóa không tồn tại trả giá trị mặc định (0) và bản thân xsim/VCS có thể cảnh báo. Rủi ro: DUT dmem mặc định khác (ví dụ X hoặc 0). Cần quyết định “bộ nhớ chưa ghi” = 0 hay X, và đồng bộ hai phía (hoặc coi đọc ô chưa ghi là lỗi stimulus). Mẹo: dùng exists() khi đọc và uvm_warning nếu chưa ghi.

Khi nào dùng DPI-C ISS (Spike) thay vì viết SV?

Khi cần độ tin cậy/độ phủ ISA lớn (RV32IMC, CSR, trap) mà viết lại tốn công và dễ sai; ISS có sẵn đã được cộng đồng kiểm chứng. Đánh đổi: tích hợp DPI-C (import/export), đồng bộ trạng thái, chi phí debug. Với 19 lệnh ở lab này, SV thuần là hợp lý và dễ học; để ngỏ giao diện (step() → retire item) để sau này thay bằng DPI mà scoreboard không đổi.
