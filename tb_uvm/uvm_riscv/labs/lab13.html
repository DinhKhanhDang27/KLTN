Tổng quan lab
  • Lab này làm gì: mô hình hóa các word data-memory như "thanh ghi" (register model kiểu RAL): mỗi word có giá trị mirror. Truy cập frontdoor = qua lệnh thật (LW/SW chạy trên pipeline); backdoor = peek/poke mảng u_dmem.mem. So mirror ↔ frontdoor ↔ backdoor để kiểm đường dữ liệu bộ nhớ nhất quán.
  • Tạo ra file nào: tb/ral/riscv_mem_regmodel.sv (mirror + API), tb/seq/riscv_mem_access_seq.sv (sinh LUI/ADDI/SW/LW), test ral_test.
  • Nhận gì từ lab trước: driver/monitor/scoreboard, backdoor peek_reg/peek_mem (Lab 1); poke_mem chưa có — sẽ thêm ở Iteration 2.
  • Lab sau dùng để làm gì: Lab 15 (bản Avalon) dùng uvm_reg thật với adapter/predictor trên bus — đây là bước đệm khái niệm.
Trọng tâm UVM của lab
  • RAL thật: uvm_reg_field → uvm_reg → uvm_reg_block → uvm_reg_map, uvm_mem; desired / mirrored / actual.
  • API cốt lõi: write/read (frontdoor) · peek/poke (backdoor) · mirror · update · set/get · predict.
  • Adapter & predictor: vai trò, vì sao cần explicit prediction; auto-predict nguy hiểm khi nào.
  • Frontdoor/backdoor tùy biến khi DUT không có bus (đúng tình huống core này): uvm_reg_frontdoor, uvm_reg_backdoor.
  • Bản chạy ở lab là RAL-like (nhẹ); phần UVM RAL đầy đủ là tham khảo kiến thức để bạn hiểu mapping khái niệm.
Vì sao "RAL-like" chứ không uvm_reg đầy đủ? riscv_pipeline_top không có bus — LW/SW đi thẳng vào u_dmem nội bộ. uvm_reg cần adapter bus (address/read/ write). Nên ở đây ta làm mô hình register nhẹ: frontdoor = chương trình lệnh, backdoor = hierarchical. Bản riscv_avalon_wrapper (Lab 15) mới có Avalon-MM để gắn uvm_reg chuẩn.

2. Vị trí trong testbench

 riscv_mem_regmodel.mirror[addr]
   frontdoor write: seq LUI/ADDI(build data) + SW addr   -> pipeline -> u_dmem
   frontdoor read : seq LW xd, addr                       -> retire wb_data
   backdoor       : vif.peek_mem(addr) / poke             -> u_dmem truc tiep
   predict/compare: mirror == frontdoor == backdoor

3. Mục tiêu học

  • Khái niệm register model: mirror (giá trị kỳ vọng) vs giá trị thật.
  • Frontdoor (qua giao thức/lệnh) vs backdoor (hierarchical) — khi nào dùng cái nào.
  • Predict: cập nhật mirror khi ghi; compare khi đọc.
  • Ánh xạ địa chỉ → "thanh ghi" (word).

6. Lý thuyết ngắn — mirror / frontdoor / backdoor (+ RAL thật)

  1. Mirror: phần mềm giữ bản sao giá trị kỳ vọng; mỗi ghi cập nhật mirror (predict).
  2. Frontdoor: ghi/đọc qua đường thật (LW/SW thực thi). Kiểm toàn bộ đường dữ liệu (ALU địa chỉ, mem, load-use). Chậm (tốn chu kỳ).
  3. Backdoor: peek/poke mảng bộ nhớ trực tiếp. Tức thì, dùng để nạp nhanh/so sánh — nhưng bỏ qua đường thật.
  4. Nhất quán 3 chiều: sau 1 SW frontdoor: mirror == backdoor peek; LW frontdoor trả đúng mirror. Lệch → lỗi memory path.

6.7. Khung RAL đầy đủ cho dmem (tham khảo)

class riscv_dmem_block extends uvm_reg_block;
  `uvm_object_utils(riscv_dmem_block)
  rand uvm_mem dmem;
  uvm_reg_map  map;
  function new(string name = "riscv_dmem_block");
    super.new(name, UVM_NO_COVERAGE);
  endfunction
  virtual function void build();
    dmem = new("dmem", 512, 32, "RW");      // 512 word × 32 bit = 2 KB
    dmem.configure(this);
    map = create_map("map", 'h0, 4, UVM_LITTLE_ENDIAN);   // base=0, 4 byte/word
    map.add_mem(dmem, 'h0, "RW");           // tham số thứ 5 có thể truyền frontdoor tùy biến
    lock_model();
  endfunction
endclass

// Backdoor tùy biến vì DUT lưu byte (mem[addr]) chứ không phải mảng 32-bit mà hdl_path trỏ được
class riscv_dmem_backdoor extends uvm_reg_backdoor;
  `uvm_object_utils(riscv_dmem_backdoor)
  virtual riscv_if vif;
  function new(string name = "riscv_dmem_backdoor"); super.new(name); endfunction
  virtual function void read_func(uvm_reg_item rw);
    rw.value[0] = vif.peek_mem(rw.offset * 4);
    rw.status   = UVM_IS_OK;
  endfunction
  virtual task write(uvm_reg_item rw);
    vif.poke_mem(rw.offset * 4, rw.value[0]);       // poke_mem: thêm vào interface (Iteration 2)
    rw.status = UVM_IS_OK;
  endtask
endclass

Gắn: blk.dmem.set_backdoor(bd);. Dùng: blk.dmem.write(status, 8, 32'hDEADBEEF, .path(UVM_FRONTDOOR)), blk.dmem.peek(status, 8, v), blk.dmem.read(status, 8, v, .path(UVM_BACKDOOR)).

6.8. Frontdoor khi không có bus

RAL chuẩn giả định có adapter dịch uvm_reg_bus_op ↔ transaction bus. Core này không có bus nên “frontdoor” là chạy chương trình LW/SW. Hai cách:

  • uvm_reg_frontdoor tùy biến: body() dùng rw_info.kind/offset/value[0] để chạy riscv_mem_access_seq trên sequencer, rồi điền kết quả (đọc x2 sau drain) vào rw_info.value[0] và rw_info.status.
  • Đổi DUT sang Avalon (Lab 15): có bus thật → viết uvm_reg_adapter (reg2bus/bus2reg) và dùng frontdoor mặc định + uvm_reg_predictor nối từ monitor bus.
Auto-predict vs explicit: map.set_auto_predict(1) cập nhật mirror ngay khi thao tác RAL hoàn tất — đủ nếu chỉ RAL truy cập DUT. Nếu còn master khác (CPU chạy firmware ghi dmem, DMA) thì mirror lỗi thời. Dùng uvm_reg_predictor + monitor để bắt mọi giao dịch bus (explicit/passive prediction).

  • uvm_reg_bit_bash_seq — ghi/đọc từng bit.

7. Iteration 0 — regmodel + frontdoor/backdoor

tb/ral/riscv_mem_regmodel.sv 
// tb/ral/riscv_mem_regmodel.sv — mô hình register NHẸ cho data memory (RAL-like)
`ifndef RISCV_MEM_REGMODEL_SV
`define RISCV_MEM_REGMODEL_SV
class riscv_mem_regmodel extends uvm_object;
  `uvm_object_utils(riscv_mem_regmodel)
  bit [31:0] mirror [int];      // addr(word-aligned) -> giá trị kỳ vọng

  function new(string name="riscv_mem_regmodel"); super.new(name); endfunction

  // predict: cập nhật mirror khi (dự định) ghi
  function void predict(int addr, bit [31:0] data);
    mirror[addr & ~3] = data;
  endfunction

  function bit [31:0] get_mirror(int addr);
    int a = addr & ~3;
    return mirror.exists(a) ? mirror[a] : 32'd0;
  endfunction

  // backdoor read/write qua vif
  function bit [31:0] read_backdoor(virtual riscv_if vif, int addr);
    return vif.peek_mem(addr);
  endfunction
  // (poke backdoor: thêm task vào interface nếu muốn ghi thẳng - ở đây chỉ đọc)

  // so mirror vs backdoor
  function bit check_backdoor(virtual riscv_if vif, int addr);
    bit [31:0] bd = read_backdoor(vif, addr);
    if (bd !== get_mirror(addr)) begin
      `uvm_error("RAL", $sformatf("MEM[0x%08h]: backdoor=0x%08h mirror=0x%08h",
                 addr, bd, get_mirror(addr)))
      return 0;
    end
    return 1;
  endfunction
endclass
`endif
tb/seq/riscv_mem_access_seq.sv (frontdoor: build const + SW + LW) 
// Sinh chuỗi: nạp hằng 'data' vào xtmp, SW xtmp->addr, rồi LW xrd<-addr.
// Dùng x0 làm base (addr = imm). data xây bằng LUI (bit 31:12) + ADDI (bit 11:0).
`ifndef RISCV_MEM_ACCESS_SEQ_SV
`define RISCV_MEM_ACCESS_SEQ_SV
class riscv_mem_access_seq extends riscv_prog_base_seq;
  `uvm_object_utils(riscv_mem_access_seq)
  rand bit [31:0] data;
  rand bit [11:0] addr;              // trong 0..2047, căn chỉnh 4
  constraint c_addr { addr inside {[0:2044]}; addr % 4 == 0; }
  function new(string name="riscv_mem_access_seq"); super.new(name); endfunction

  // phát 1 item raw
  task raw(bit [31:0] w);
    riscv_seq_item it = riscv_seq_item::type_id::create("it");
    start_item(it); void'(it.randomize());
    it.use_raw=1; it.raw_word=w; it.last_instr=0;
    finish_item(it);
  endtask

  // body override: xây data vào x1, SW x1->addr, LW x2<-addr, halt
  task body();
    bit [19:0] hi = data[31:12] + data[11];     // bù khi ADDI sign-extend
    bit [11:0] lo = data[11:0];
    // lui x1, hi
    raw({hi, 5'd1, 7'b0110111});
    // addi x1, x1, lo
    raw({lo, 5'd1, 3'b000, 5'd1, 7'b0010011});
    // sw x1, addr(x0)   (S-type: imm[11:5]|rs2|rs1|f3|imm[4:0]|op)
    raw({addr[11:5], 5'd1, 5'd0, 3'b010, addr[4:0], 7'b0100011});
    // lw x2, addr(x0)
    raw({addr, 5'd0, 3'b010, 5'd2, 7'b0000011});
    // halt
    if (append_halt) begin
      riscv_seq_item h = riscv_seq_item::type_id::create("halt");
      start_item(h); void'(h.randomize());
      h.use_raw=1; h.raw_word=32'h0000006f; h.last_instr=1;
      finish_item(h);
    end
  endtask
endclass
`endif
Mẹo hằng số: addi sign-extend imm[11]. Nếu lo có bit11=1, phần lo bị trừ → bù bằng hi = data[31:12] + data[11]. Đây là thủ thuật dựng hằng 32-bit kinh điển của RV32I (li giả lệnh).

`ifndef RAL_TEST_SV
`define RAL_TEST_SV
class ral_test extends riscv_base_test;
  `uvm_component_utils(ral_test)
  riscv_mem_regmodel rm;
  function new(string n,uvm_component p); super.new(n,p); endfunction
  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    rm = riscv_mem_regmodel::type_id::create("rm");
  endfunction
  task run_phase(uvm_phase phase);
    riscv_mem_access_seq s = riscv_mem_access_seq::type_id::create("s");
    phase.raise_objection(this);
    assert(s.randomize() with { data==32'hDEAD_BEEF; addr==32; });
    rm.predict(32, 32'hDEADBEEF);            // predict TRƯỚC khi chạy
    s.start(env.agent.sqr);

              cfg.vif.peek_reg(2), cfg.vif.peek_mem(32), rm.get_mirror(32)), UVM_LOW)
    phase.drop_objection(this);
  endtask
endclass
`endif

Iteration 1 — random nhiều (addr,data) rồi check_backdoor từng cái

Iteration 2 — backdoor poke rồi frontdoor LW đọc lại

  task automatic poke_mem(input int byte_addr, input logic [31:0] data);
    int b; b = byte_addr & 11'h7fc;
    {dut.u_dmem.mem[b+3], dut.u_dmem.mem[b+2], dut.u_dmem.mem[b+1], dut.u_dmem.mem[b]} = data;

LW (frontdoor) đọc đúng giá trị poke (backdoor). Dạy: backdoor ghi nhanh để set tiền đề, frontdoor kiểm đường đọc.

rm.predict(32, 32'h0) nhưng SW ghi DEADBEEF.

Khác biệt

Iteration 4 — địa chỉ không căn chỉnh (test âm)

Ép addr=34 (lệch 2). DUT căn chỉnh xuống 32 (addr[1:0] bỏ).

Khác biệt

Ghi/đọc rơi vào word 32; mirror theo địa chỉ căn chỉnh. Dạy: hành vi căn chỉnh của data_memory (liên kết Lab 14 misalign).

Iteration 5 — ghi chú map SHA (0x02008000) ngoài vùng dmem

Thử SW vào 0x02008000 — ngoài 2KB dmem của pipeline (không có SHA).

Khác biệt

12. Phỏng vấn — hỏi & đáp

Bấm câu hỏi để xem đáp án — nên tự trả lời miệng trước khi mở. Mỗi câu có ví dụ cụ thể như khi bị hỏi trong phỏng vấn.

Giải thích desired, mirrored và actual của một register; update() và mirror() làm gì?

Desired: giá trị ta muốn; mirrored: giá trị RAL tin DUT đang có; actual: giá trị thật. set(5) đổi desired. update() ghi xuống DUT chỉ nếu desired ≠ mirrored (và cập nhật mirrored). mirror(UVM_CHECK) đọc DUT rồi so với mirrored (báo lỗi nếu khác) — chính là kiểm thanh ghi tự động.

blk.ctrl.set(32'h1);          // desired = 1
blk.ctrl.update(status);      // desired(1) != mirrored(0) → ghi DUT
blk.ctrl.mirror(status, UVM_CHECK);   // đọc DUT, so với mirrored
write() / read() khác poke() / peek()? Backdoor có cập nhật mirror không?

write/read: dùng path mặc định của map (thường frontdoor, tốn thời gian mô phỏng); có thể ép .path(UVM_BACKDOOR). poke/peek: luôn backdoor (0 thời gian). Cả hai đường đều cập nhật mirror (qua predict). Nhớ rằng backdoor bỏ qua hành vi thật (side-effect, access policy) nên chỉ dùng setup/ kiểm chéo.

Adapter và predictor khác nhau thế nào? Khi nào cần predictor?

Adapter (uvm_reg_adapter): dịch thao tác RAL ↔ transaction bus (reg2bus, bus2reg). Predictor (uvm_reg_predictor): nghe monitor bus, dùng adapter bus2reg để cập nhật mirror cho mọi giao dịch bus — kể cả do master khác. Cần predictor khi DUT có nhiều master hoặc register có side-effect (read-to-clear) cần mô hình hóa đúng thời điểm; với một master duy nhất auto-predict là đủ.

Vì sao core này “không có bus” thì khó dùng RAL chuẩn? Cách giải quyết?

RAL chuẩn cần frontdoor qua sequence/driver bus. Ở đây truy cập dmem là kết quả của chương trình lệnh (LW/SW) chứ không phải giao dịch bus. Giải quyết: (1) uvm_reg_frontdoor tùy biến chạy chương trình LW/SW và thu kết quả; (2) uvm_reg_backdoor tùy biến cho mảng byte; (3) hoặc nâng DUT lên wrapper Avalon rồi dùng adapter/predictor chuẩn (Lab 15). Lab này dùng bản “RAL-like” để bạn nắm khái niệm trước.

Backdoor hdl_path và custom backdoor: khi nào cần cái nào?

add_hdl_path("tb.dut", "RTL") + add_hdl_path_slice khi RTL có biến khớp register (cùng độ rộng/tên) — UVM tự sinh đường dẫn và dùng uvm_hdl_* (DPI) đọc/ghi. Custom backdoor khi cấu trúc RTL khác mô hình (mảng byte thay vì word, register chia tách bit, giá trị mã hóa). dmem này là mảng byte ⇒ custom backdoor (hoặc 4 lần uvm_hdl_read ghép).

Nêu các built-in sequence của RAL và mục đích. Bạn dùng cái nào cho dmem?

uvm_reg_hw_reset_seq (giá trị reset), uvm_reg_bit_bash_seq (từng bit), uvm_reg_access_seq (frontdoor vs backdoor), uvm_mem_walk_seq (walking pattern kiểm địa chỉ/dữ liệu), uvm_mem_access_seq. Với dmem: uvm_mem_walk_seq + uvm_mem_access_seq — kiểm memory path độc lập với chương trình. Điều kiện: model phải lock_model() và đã gán frontdoor/backdoor phù hợp.

RAL có thay scoreboard không? Chúng phối hợp thế nào?

Không. RAL chuyên cho register/memory-mapped state (mirror + kiểm). Scoreboard kiểm luồng dữ liệu/chức năng. Phối hợp: scoreboard có thể hỏi blk.reg.get_mirrored_value() làm giá trị kỳ vọng cấu hình (ví dụ chế độ hoạt động), RAL kiểm mirror(UVM_CHECK) cuối test như “sweep thanh ghi”. Ở lab: mirror dmem ↔ sweep Lab 11 là hai mặt cùng một ý tưởng.

Frontdoor đọc dmem qua LW bị ảnh hưởng bởi lỗi forwarding/stall. Điều đó tốt hay xấu cho kiểm tra?

Tốt: frontdoor kiểm cả datapath (ALU địa chỉ, load-use, writeback) — lỗi forwarding làm giá trị đọc sai sẽ hiện ở mismatch giữa frontdoor ↔ backdoor ↔ mirror. Xấu: khó tách lỗi nằm ở memory hay ở forwarding; cần backdoor so sánh để định vị: backdoor OK + frontdoor sai ⇒ lỗi datapath, không phải bộ nhớ.

13. Cheat-sheet

class riscv_mem_regmodel; bit[31:0] mirror[int];
  predict(addr,data){ mirror[addr&~3]=data; }
  check_backdoor(vif,addr){ assert vif.peek_mem(addr)==get_mirror(addr); }
// frontdoor const: LUI x1,(hi+bit11); ADDI x1,x1,lo; SW x1,addr(x0); LW x2,addr(x0)

14. Bài tập code & câu hỏi nâng cao UVM

8 bài rèn tay, tăng dần độ khó. Làm trên baseline của lab này; đáp án chỉ là hướng tham khảo — giá trị nằm ở việc bạn tự gõ, chạy và đọc log.

0 / 8 bài đã làm
★ Dễ

EX1 — Ánh xạ khái niệm

Viết bảng 2 cột: mỗi thành phần của riscv_mem_regmodel/ral_test ↔ lớp/hàm UVM RAL tương ứng (ít nhất 6 dòng). Đánh dấu chỗ nào “RAL-like thiếu”.
Gợi ý & đáp án tham khảo

Thiếu: adapter/predictor, uvm_reg_map (địa chỉ ↔ offset), access policy (RO/WO), lock_model, built-in sequences, coverage của register.

★ Dễ

EX2 — Thêm poke_mem

Thêm task poke_mem(int addr, bit [31:0] data) vào riscv_if (ghi 4 byte). Viết test: poke addr 64, rồi chạy LW frontdoor và kiểm giá trị. Vì sao poke xong cần đồng bộ mirror?
Gợi ý & đáp án tham khảo

Nếu không gọi rm.predict(64, data) sau poke thì mirror lỗi thời → check_backdoor báo lệch. Trong RAL thật, poke() tự predict.

★★ Vừa

EX3 — Mirror check bằng frontdoor

Viết check_frontdoor(addr): chạy riscv_mem_access_seq với LW, chờ retire, lấy x2 (backdoor peek_reg) và so với mirror. Thảo luận khác biệt với check_backdoor.
Gợi ý & đáp án tham khảo

Frontdoor kiểm cả datapath. Backdoor kiểm nội dung bộ nhớ. Hai kiểm chéo giúp định vị lỗi (xem câu hỏi cuối mục 12).

★★ Vừa

EX4 — Regfile như uvm_reg_block

Dựng riscv_regfile_block với 31 uvm_reg (x1…x31, mỗi cái 1 field 32-bit) và hdl_path u_regfile.registers[N]. Dùng peek() để đọc và mirror(UVM_CHECK, UVM_BACKDOOR). Viết ngắn gọn: vì sao x0 không nên mô hình hóa là reg ghi được?
Gợi ý & đáp án tham khảo

x0 bất biến (RO = 0) — mô hình hóa bằng access policy "RO" với reset value 0. Bài này còn là ví dụ tốt về mỗi thanh ghi một add_hdl_path_slice.

★★ Vừa

EX5 — Built-in sequence

Dùng uvm_mem_walk_seq trên riscv_dmem_block (chỉ backdoor). Tại sao walk dùng backdoor phù hợp ở đây? Điều gì cần để chạy với frontdoor?
Gợi ý & đáp án tham khảo

Frontdoor cần uvm_reg_frontdoor đã hoàn thiện (chạy chương trình cho mỗi truy cập — rất chậm: mỗi word cần ≥ 4 lệnh + drain). Thực tế: mem walk chủ yếu backdoor cho nhanh, frontdoor sample cho vài địa chỉ.

★★★ Khó

EX6 — uvm_reg_frontdoor tùy biến

Hiện thực riscv_dmem_frontdoor: body() sinh riscv_mem_access_seq theo rw_info.kind (WRITE/READ), chờ drain, trả kết quả. Gắn qua map.add_mem(…, frontdoor). Chạy dmem.write() và dmem.read().
Gợi ý & đáp án tham khảo

Khó nhất: mỗi lần RAL truy cập ta cần một chương trình mới chạy sau reset → driver Lab 3 reset mỗi chương trình, nên mỗi write/read = một “chương trình độc lập”: tùy RTL, reset có thể xóa dmem (mất dữ liệu đã ghi) và ISS/mirror phải đồng bộ theo. Giải pháp: cho driver một chế độ “không reset” khi chạy frontdoor liên tiếp — hoặc dùng bản Avalon (Lab 15). Đây là bài tập về trade-off kiến trúc.

★★★ Khó

EX7 — Explicit predictor mô phỏng

Viết riscv_dmem_predictor (subscriber của riscv_retire_item): khi mem_write thì rm.predict(addr, wdata) — mirror cập nhật từ quan sát thay vì từ test. So với predict thủ công ở ral_test.
Gợi ý & đáp án tham khảo

Đây chính là uvm_reg_predictor thu nhỏ: mirror bám theo mọi giao dịch quan sát, không chỉ giao dịch do RAL khởi tạo — nên bắt được cả firmware ghi dmem.

★★★ Khó

EX8 — Tìm lỗi bằng ba nguồn

Chèn lỗi RTL: lw trả sai khi load-use xảy ra ngay sau sw cùng địa chỉ. Chạy ral_test và dùng ba nguồn (mirror, backdoor, frontdoor) để định vị lỗi: bộ nhớ hay datapath?
Gợi ý & đáp án tham khảo

Backdoor == mirror (bộ nhớ đúng), frontdoor ≠ mirror (đường đọc sai) ⇒ lỗi forwarding/load-use, không phải bộ nhớ. Mẫu suy luận này là kỹ năng debug cốt lõi.
