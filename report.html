Hướng Dẫn Chạy Đo Chu Kỳ Phần Cứng / Phần Mềm SHA-256

Dưới đây là hướng dẫn chi tiết từng bước (step-by-step) với chính xác các câu lệnh dựa trên cấu trúc thư mục dự án hiện tại.

GIAI ĐOẠN 1: TẠO VÀ ĐÓNG GÓI DỮ LIỆU INPUT

Mở Terminal / PowerShell tại thư mục gốc của dự án (~/Study/KLtN/code).

Bước 1: Tạo file text chứa dữ liệu đầu vào

Chạy lệnh sau để ghi chuỗi dữ liệu (ví dụ: "Dinh Khanh Dang") vào file message.txt bên trong thư mục docs/:

echo -n "Dinh Khanh Dang" > docs/message.txt

Bước 2: Chạy script đóng gói dữ liệu thành TCL script

python scripts/pack_sdram_input.py docs/message.txt -o scripts/load_sdram_input.tcl
Kết quả mong đợi: Terminal sẽ in ra thông số độ dài chuỗi và một dòng chứa mã SHA-256 thực tế (PC tính toán). Hãy copy dòng mã băm này lại để đối chiếu ở phần cuối.

GIAI ĐOẠN 2: ĐO CHU KỲ PHẦN MỀM (SOFTWARE HASHING)

Bước 1: Biên dịch Firmware Mềm

Chạy lệnh sau để chuyển mã Assembly của phần mềm thành file HEX:

python scripts/asm_to_hex.py firmware/firmware_soft_sha256_timer.S -o firmware/firmware.hex
Lưu ý: Cấu hình hệ thống Qsys đã được tự động trỏ đến file firmware/firmware.hex, nên bạn không cần phải chạy lệnh copy đè vào hệ thống như quy trình cũ.

Bước 2: Compile (Biên dịch) toàn bộ Quartus Project

Bạn mở giao diện Quartus, chọn Processing -> Start Compilation.
Hoặc nếu chạy trên command line, sử dụng:

quartus_sh --flow compile KLTN_SHA256_RISCV
Kết quả mong đợi: Quá trình compile chạy thành công (0 errors), sinh ra file bitstream cấu hình tại output_files/KLTN_SHA256_RISCV.sof.

Bước 3: Nạp FPGA

  • Bật mạch, cắm cáp USB-Blaster.
  • Mở Quartus Programmer, chọn Hardware Setup là USB-Blaster.
  • Chọn Add File output_files/KLTN_SHA256_RISCV.sof, đánh dấu tick "Program/Configure" rồi bấm Start.

Bước 4: Nạp dữ liệu Input xuống SDRAM

Mở phần mềm Nios II Command Shell, sau đó gõ:

system-console

Trong cửa sổ System Console, lần lượt gõ các lệnh sau để trỏ đến thư mục làm việc và nạp script dữ liệu TCL vừa tạo:

refresh_connections
get_service_paths master
cd [pwd]  # (Hoặc gõ chính xác đường dẫn: cd {C:/.../code})
source scripts/load_sdram_input.tcl
Kết quả mong đợi: System Console sẽ in ra magic = 0x53484132 (báo hiệu dữ liệu đã ghi xuống SDRAM thành công).

Bước 5: Xem kết quả băm và chu kỳ phần mềm

Để terminal cũ của Nios qua một bên (hoặc mở cửa sổ Nios II Command Shell mới), chạy lệnh:

nios2-terminal
Kết quả mong đợi: Bo mạch in lên màn hình Terminal chuỗi mã SHA-256 giống hệt với mã đã copy ở Giai đoạn 1. Kế bên dưới, nó sẽ in ra tổng số lượng chu kỳ (Software Cycles) đã dùng.
Tắt terminal này bằng phím Ctrl + C.

GIAI ĐOẠN 3: ĐO CHU KỲ PHẦN CỨNG (HARDWARE ACCELERATOR)

Bước 1: Biên dịch Firmware Cứng

Trở lại Terminal gốc của dự án, biên dịch mã Assembly dành riêng cho Hardware IP đè lên file hex cũ:

python scripts/asm_to_hex.py firmware/firmware_sha256_ip_timer.S -o firmware/firmware.hex

Bước 2: Compile lại Quartus Project

Giống như trên, mở Quartus và chọn Processing -> Start Compilation (để nó build firmware cứng mới vào bộ nhớ FPGA).

Bước 3: Nạp FPGA lần 2

Mở Quartus Programmer nạp lại file .sof vừa build đè xuống bo mạch (thao tác y hệt bước 3 của GĐ2). Mạch sẽ bị reset.

Bước 4: Nạp lại dữ liệu Input xuống SDRAM

Vì mạch vừa bị reset, dữ liệu ở SDRAM có thể mất đồng bộ. Trở lại cửa sổ System Console (nếu chưa tắt) và chạy lại lệnh nạp:

source scripts/load_sdram_input.tcl

Bước 5: Xem kết quả băm và chu kỳ phần cứng

Mở lại Nios II Command Shell và gõ:

nios2-terminal
Kết quả mong đợi cuối cùng: Trên màn hình sẽ xuất hiện đoạn mã SHA-256 hoàn toàn trùng khớp với Giai đoạn 1 và 2. Nhưng lần này, con số Hardware Cycles (số chu kỳ phần cứng) được in ra sẽ nhỏ hơn rất rất nhiều so với con số ở Giai đoạn 2. Đó chính là minh chứng cho việc IP Hardware tăng tốc việc tính toán!
