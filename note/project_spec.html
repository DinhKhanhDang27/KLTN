SoC System Specification: RISC-V & SHA-256

1. System Overview & Memory Map

  • Clock Frequency: 50 MHz
  • Target FPGA: Cyclone IV E (EP4CE22F17C6)
  • Bus Architecture: Avalon Memory-Mapped (Avalon-MM)
  • System Master: Custom RISC-V Core
  • Debug Master: JTAG to Avalon Master (Bypasses CPU for direct bus access)

1.1 Global Address Map

2. RISC-V Core Specification

  • Module Wrapper: riscv_avalon_wrapper
  • Bus Role: Avalon-MM Master

2.1 Datapath & Registers

  • Internal Architecture: 64-bit ALU & Register File
  • Register File: 32 x 64-bit General Purpose Registers (x0 hardwired to 0)
  • Bus Interface: 32-bit Address & Data Bus (avm_writedata[31:0], avm_readdata[31:0])
  • Byte Enable: Fixed at 4'hf (32-bit aligned memory access only)

2.2 Pipeline & Synchronization

  • Execution Model: Multi-cycle FSM (STATE_RUN, STATE_WAIT_READ)
  • Load Operation: CPU stalls in STATE_WAIT_READ until avm_readdatavalid is asserted
  • Store Operation: CPU waits on avm_waitrequest assertion

2.3 Instruction Set Architecture (ISA) Support

  • R-Type & I-Type: Standard Arithmetic, Logic, and Shift operations
  • Branch & Jump: B-Type (Branch), JAL, JALR
  • Memory: Load/Store instructions via Avalon-MM
  • U-Type: LUI, AUIPC
  • Custom Extension (Decoded but floating): sha2rst, sha2push, sha2start, sha2perform, sha2finish, sha2read

3. SHA-256 Hardware Accelerator

  • Bus Role: Avalon-MM Slave
  • Read Latency: 0 Cycles (Combinational Read)
  • Hash Throughput: ~64 clock cycles per 512-bit block

3.1 Register Map (32-bit Word Aligned)

Word Addr Offset Access Register Name Bitfield Description
0x00 - 0x0F 0x00 - 0x3C R/W DATA_BLOCK - 16-word (512-bit) message block
- Big-Endian: Addr 0x00 = MSB, Addr 0x0F = LSB
- Note: Software must perform NIST padding before loading
0x10 0x40 R/W CONTROL - Bit [0] start : Write 1 to trigger hash execution (Auto-clears)
- Bit [1] init : Write 1 to initialize NIST IV (First block only)
- Bit [2] irq_en: Write 1 to enable hardware interrupt output
0x11 R/W
(W-1-to-C)		 STATUS - Bit [0] ready : 1 = Idle/Ready, 0 = Busy computing
- Bit [1] hash_valid : 1 = Hash computation complete
- Bit [2] irq_pending: 1 = Interrupt pending (Write 1 to clear)
0x12 - 0x19 0x48 - 0x64 R-Only HASH_OUT - 8-word (256-bit) computed digest
- Sequential read from Addr 0x12 (MSB) to 0x19 (LSB)

3.2 Operational Protocol (Polling Mode)

  • Step 1: Write 16-word padded block to DATA_BLOCK (0x00 - 0x0F).
  • Step 2: Write 0x3 (start=1, init=1) to CONTROL (0x10).
  • Step 3: Poll STATUS (0x11). Wait until (STATUS & 0x2) != 0.
  • Step 4: Sequential Read 8 words from HASH_OUT (0x12 - 0x19).
Interrupt Mode Protocol: Enable irq_en in CONTROL. Await hardware IRQ assertion. Read HASH_OUT. Write 0x4 to STATUS to clear irq_pending.

4. Suggested Testcases (Coverage Driven)

To achieve 100% Code Coverage (Line, Toggle, and FSM) for the SHA-256 IP, implement the following sequences in your UVM testbench:

Testcase Name Description & Execution Targeted Coverage Logic
TC01: Multi-Block Hash Hash a string longer than 55 bytes (e.g., 200 bytes). This will force the sequence to chunk the data into multiple 512-bit blocks. Exercises the init = 0 logic path in the hardware, ensuring the core successfully re-uses previous h_reg states without resetting NIST constants.
TC02: Interrupt (IRQ) Mode Write 0x7 to CONTROL (start=1, init=1, irq_en=1). Do not poll STATUS. Wait for the physical irq pin to assert. Then write 0x4 to STATUS to clear it. Exercises the irq_enable, irq_pending flip-flops, and the Write-1-to-Clear logic in the Avalon Wrapper.
TC03: Byte-Enable Write Instead of writing full 32-bit words, write data byte-by-byte or half-word by half-word by controlling the Avalon avm_byteenable signal (e.g., 4'b0001, 4'b0011). Directly covers the 4 separate if (avs_byteenable[X]) branch conditions inside the sha256Wrapper.sv write logic.
TC04: Zero-Length Edge Case Hash an empty string (Length = 0 bytes). The data block will only contain the 0x80 byte at Word 0 and the length 0x0 at Word 15. Verifies algorithm robustness and mathematical correctness against the minimum boundary edge case.
