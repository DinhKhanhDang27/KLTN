  3) Critical path (what limits Fmax)
-------------------------------------------------------------------
  Worst setup path (85C):
     From : exmem_rd_r[3]   (EX/MEM pipeline register)
     To   : ifid_instr[*]   (IF/ID instruction register)
     Data delay : ~13.0 ns  ->  1/13.0ns ~= 76.3 MHz
  The bottleneck is the fetch/decode path interacting with the
  EX/MEM stage (instruction memory read feeding IF/ID). To push Fmax
  higher, pipeline/register the instruction-memory read path.

-------------------------------------------------------------------
  4) About the negative slack in the .sta.rpt
-------------------------------------------------------------------
  The SDC constrains clk to 5.000 ns (200 MHz) ON PURPOSE, so the
  design does not get artificially capped. At 200 MHz it fails setup
  (worst slack = -8.108 ns) - this is EXPECTED and is NOT an error.
  The achievable frequency is the "Report Fmax" value above
  (76.29 MHz), which is what you quote.

  On the real DE0-Nano the on-board oscillator is 50 MHz, so the core
  runs comfortably within timing (76.29 MHz > 50 MHz).
