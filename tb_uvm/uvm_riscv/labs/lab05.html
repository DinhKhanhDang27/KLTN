6. Lý thuyết ngắn — cây component & phase (+ UVM bên trong)

  1. build_phase (top→đáy): tạo con, đọc config. connect_phase (đáy→top): nối TLM port. run_phase: chạy, có objection.
  2. config_db: top set vif + cfg; component get ở build. Khóa theo đường dẫn & tên field.
  3. Agent ACTIVE/PASSIVE: dùng lại cùng agent cho môi trường chủ động (có stimulus) hay chỉ giám sát (passive) bằng cách đổi is_active.
  4. Package: compile một lần, import ở test/top. Include guard tránh lỗi "đã định nghĩa".

6.5. Toàn bộ phase của UVM và hướng chạy

Giữa run_phase còn 12 runtime phase (reset/configure/main/shutdown…) chạy song song với run_phase; phần lớn dự án dùng run_phase thuần. Chỉ run_phase (và runtime phases) là task — tức là chỉ ở đó mới tiêu thời gian.

6.6. Objection — cơ chế kết thúc

run_phase kết thúc khi tổng objection của cả cây = 0. Mỗi raise_objection tăng bộ đếm, drop_objection giảm. Hết thì UVM chờ thêm drain_time (nếu có), rồi kill mọi tiến trình run_phase còn lại.

phase.raise_objection(this, "test running");          // nên mô tả để thấy trong +UVM_OBJECTION_TRACE
...
phase.phase_done.set_drain_time(this, 200ns);          // cho monitor/scoreboard xả nốt
phase.drop_objection(this);
Debug: +UVM_PHASE_TRACE (xem phase chuyển), +UVM_OBJECTION_TRACE (ai raise/drop), +UVM_TIMEOUT=100000,NO (watchdog toàn cục).

6.7. config_db — quy tắc mà phỏng vấn hay hỏi

  • Khớp theo 3 thứ: kiểu T, đường dẫn (cntxt + inst_name khớp với get_full_name() của người get), và tên field.
  • Ưu tiên: set từ cấp cao hơn trong hierarchy thắng cấp thấp (test thắng env thắng agent); cùng cấp thì set sau thắng.
  • Wildcard: "*", "env.agent*" hợp lệ trong inst_name.
  • Thời điểm: set phải trước build_phase của component get. Cha set trong build của mình trước khi tạo con là an toàn.
  • Kiểu: int ≠ int unsigned ≠ bit [31:0] → fail im lặng (get trả 0).
// Test set vif ở scope tuyệt đối từ null:
uvm_config_db#(virtual riscv_if)::set(null, "uvm_test_top", "vif", vif);
//  → component get với get(this,"","vif",v) chỉ thấy nếu this.get_full_name() == "uvm_test_top" hoặc khớp pattern.
//    Env/agent KHÔNG thấy; vì vậy test get rồi đưa vào cfg.vif và set lại xuống env/agent (pattern lab).

6.8. Config object vs. từng field

Gom tham số vào một uvm_object (riscv_agent_config): một set/một get, thêm tham số mới không đụng chỗ truyền, có thể randomize config (config-space random), có copy/print. Nhược: handle chia sẻ — agent sửa cfg thì người khác thấy. Muốn bất biến: clone() ở người nhận hoặc cfg chỉ có getter.

6.9. type_id::create thật sự làm gì

`uvm_component_utils(T) tạo T::type_id = uvm_component_registry#(T,"T") và đăng ký vào uvm_factory singleton lúc elaboration. create(name,parent) hỏi factory: có instance override khớp parent.get_full_name()+"."+name không? có type override? → tạo đối tượng tương ứng. Vì vậy factory phải biết lớp con (đã biên dịch trong package) trước khi create được gọi.

uvm_factory::get().print();           // liệt kê type đã đăng ký + override đang hiệu lực
uvm_top.print_topology();             // cây component thực tế sau build

riscv_agent.sv 
`ifndef RISCV_AGENT_SV
`define RISCV_AGENT_SV
class riscv_agent extends uvm_agent;
  `uvm_component_utils(riscv_agent)
  riscv_agent_config cfg;
  riscv_sequencer    sqr;
  riscv_driver       drv;
  riscv_monitor      mon;

  function new(string name, uvm_component parent); super.new(name,parent); endfunction

  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    if (!uvm_config_db#(riscv_agent_config)::get(this,"","cfg",cfg))
      `uvm_fatal("AGT","thieu cfg")
    mon = riscv_monitor::type_id::create("mon", this);
    uvm_config_db#(virtual riscv_if)::set(this,"mon","vif",cfg.vif);
    if (cfg.is_active == UVM_ACTIVE) begin
      sqr = riscv_sequencer::type_id::create("sqr", this);
      drv = riscv_driver   ::type_id::create("drv", this);
      uvm_config_db#(virtual riscv_if)::set(this,"drv","vif",cfg.vif);
      uvm_config_db#(int unsigned)   ::set(this,"drv","drain",cfg.drain);
    end
  endfunction

  function void connect_phase(uvm_phase phase);
    if (cfg.is_active == UVM_ACTIVE)
      drv.seq_item_port.connect(sqr.seq_item_export);
  endfunction
endclass
`endif

riscv_base_test.sv 
`ifndef RISCV_BASE_TEST_SV
`define RISCV_BASE_TEST_SV
class riscv_base_test extends uvm_test;
  `uvm_component_utils(riscv_base_test)
  riscv_env          env;
  riscv_agent_config cfg;

  function new(string name, uvm_component parent); super.new(name,parent); endfunction

  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    cfg = riscv_agent_config::type_id::create("cfg");
    if (!uvm_config_db#(virtual riscv_if)::get(this,"","vif",cfg.vif))
      `uvm_fatal("TEST","top chua set vif");
    cfg.is_active = UVM_ACTIVE;
    env = riscv_env::type_id::create("env", this);
    uvm_config_db#(riscv_agent_config)::set(this,"env","cfg",cfg);
  endfunction

  // sequence mặc định (override ở test con)
  virtual function uvm_sequence#(riscv_seq_item) get_seq();
    return prog_seq::type_id::create("seq");
  endfunction

  task run_phase(uvm_phase phase);
    uvm_sequence#(riscv_seq_item) seq = get_seq();
    phase.raise_objection(this);
    seq.start(env.agent.sqr);
    repeat (30) @(posedge cfg.vif.clk);
    `uvm_info("TEST", $sformatf("x1=%0d x2=%0d x3=%0d",
              cfg.vif.peek_reg(1), cfg.vif.peek_reg(2), cfg.vif.peek_reg(3)), UVM_LOW)
    phase.drop_objection(this);
  endtask
endclass
`endif

tb/seq/prog_seq.sv (tách sequence ra file) 
`ifndef PROG_SEQ_SV
`define PROG_SEQ_SV
class prog_seq extends uvm_sequence #(riscv_seq_item);
  `uvm_object_utils(prog_seq)
  function new(string name="prog_seq"); super.new(name); endfunction
  task body();
    bit [31:0] words[] = '{32'h00500093,32'h00308113,32'h002081b3,32'h0000006f};
    foreach (words[i]) begin
      riscv_seq_item it = riscv_seq_item::type_id::create($sformatf("it%0d",i));
      start_item(it); void'(it.randomize());
      it.raw_word=words[i]; it.use_raw=1; it.last_instr=(i==words.size()-1);
      finish_item(it);
    end
  endtask
endclass
`endif
tb/top/riscv_tb_top.sv (bản chính thức — import pkg) 
`timescale 1ns/1ps
module riscv_tb_top;
  import uvm_pkg::*; import riscv_pkg::*; `include "uvm_macros.svh"

  logic clk = 0; always #5 clk = ~clk;
  riscv_if vif (.clk(clk));
  riscv_pipeline_top dut (.clk(clk), .rst(vif.rst), .out_pc(), .out_alu_result());

  // probe + shadow pipeline (như Lab 1/4)
  assign vif.pc_if=dut.pc_if; assign vif.alu_result_ex=dut.alu_result_ex;
  assign vif.stall=dut.stall; assign vif.redirect=dut.redirect;
  logic s_idex_valid,s_exmem_valid,s_memwb_valid;
  logic [31:0] s_idex_pc,s_exmem_pc,s_memwb_pc,s_idex_instr,s_exmem_instr,s_memwb_instr;
  logic s_memwb_mwrite; logic [31:0] s_memwb_maddr,s_memwb_mwdata;
  always @(posedge clk or posedge vif.rst) if(vif.rst) begin
    s_idex_valid<=0;s_exmem_valid<=0;s_memwb_valid<=0;
  end else begin
    s_idex_valid<=(dut.redirect|dut.stall)?1'b0:dut.ifid_valid;
    s_idex_pc<=dut.ifid_pc; s_idex_instr<=dut.ifid_instr;
    s_exmem_valid<=s_idex_valid; s_exmem_pc<=s_idex_pc; s_exmem_instr<=s_idex_instr;
    s_memwb_valid<=s_exmem_valid; s_memwb_pc<=s_exmem_pc; s_memwb_instr<=s_exmem_instr;
    s_memwb_mwrite<=dut.exmem_mem_write; s_memwb_maddr<=dut.exmem_alu_result; s_memwb_mwdata<=dut.exmem_store_data;
  end
  assign vif.ret_valid=s_memwb_valid; assign vif.ret_pc=s_memwb_pc; assign vif.ret_instr=s_memwb_instr;
  assign vif.ret_reg_write=dut.memwb_reg_write_r; assign vif.ret_rd=dut.memwb_rd_r; assign vif.ret_wb_data=dut.memwb_wb_value_r;
  assign vif.ret_mem_write=s_memwb_mwrite; assign vif.ret_mem_addr=s_memwb_maddr; assign vif.ret_mem_wdata=s_memwb_mwdata;

  initial begin
    uvm_config_db#(virtual riscv_if)::set(null,"uvm_test_top","vif",vif);
    run_test("riscv_base_test");
  end
endmodule

8. Iterations

Iteration 1 — agent PASSIVE (chỉ monitor)

Đặt cfg.is_active = UVM_PASSIVE trong test và bảo vệ lệnh start sequence (chỉ ACTIVE mới có env.agent.sqr), nếu không test chết ngay bằng UVM_FATAL [SEQ] neither the item's sequencer nor dedicated sequencer has been supplied (đã chạy thử):

    if (cfg.is_active == UVM_ACTIVE) seq.start(env.agent.sqr);   // trong run_phase của riscv_base_test
Khác biệt

Không dựng sequencer/driver → không nạp chương trình → không có retire (x1=0 x2=0 x3=0, Tong so lenh retire = 0). Dạy: ACTIVE/PASSIVE điều khiển có/không stimulus; passive dùng khi tích hợp với core thật đã chạy.

Iteration 2 — tạo test con sanity_test override sequence

Extends riscv_base_test, override get_seq() trả sequence khác.

Khác biệt

Chạy UVM_TESTNAME=sanity_test dùng env y hệt, chỉ đổi stimulus. Dạy: test = env + sequence chọn.

Iteration 3 — đổi cfg.drain qua config_db

Đặt cfg.drain = 12 trong test; driver get ở build.

Khác biệt

Driver nhận DRAIN mới mà không sửa code driver. Dạy: config object truyền tham số toàn testbench.

Iteration 4 — in cây topology bằng uvm_top.print_topology()

Trong end_of_elaboration_phase gọi uvm_top.print_topology().

Khác biệt

Thấy cây env→agent→sqr/drv/mon. Dạy: kiểm tra hierarchy đã dựng đúng.

Iteration 5 — quên set vif ở top (lỗi)

Comment dòng uvm_config_db#(virtual riscv_if)::set(...) ở top.

Khác biệt

UVM_FATAL [TEST] top chua set vif. Dạy: config_db set phải xảy ra trước build của component get.

12. Phỏng vấn — hỏi & đáp

Bấm câu hỏi để xem đáp án — nên tự trả lời miệng trước khi mở. Mỗi câu có ví dụ cụ thể như khi bị hỏi trong phỏng vấn.

Vì sao build_phase chạy top-down còn connect_phase bottom-up? Điều gì hỏng nếu đảo?

Cha phải tồn tại mới tạo được con → build top-down (test → env → agent → driver…). connect cần cả hai đầu đã được tạo; chạy bottom-up đảm bảo khi cha nối port của con thì các con đã nối xong phần của mình. Nếu nối trong build_phase: drv.seq_item_port.connect(sqr.seq_item_export) có thể gặp sqr == null (chưa tạo) → null deref. Quy tắc nhớ: build = tạo + cấu hình; connect = nối; không trộn.

uvm_config_db#(int)::set(this,"agt","N",5) và set(null,"*","N",9) — agent get ra bao nhiêu?

Phụ thuộc ai set ở cấp cao hơn: set(null,"*",…) từ top có ngữ cảnh null (cấp cao nhất) nên thắng → agent thấy 9, dù set(this,"agt",…) cụ thể hơn. Đây là điều gây bất ngờ: “cụ thể hơn” không thắng, “cấp cao hơn trong hierarchy” mới thắng (trừ khi cùng cấp, set sau thắng). Muốn ghi đè từ dưới: set ở cấp cao hơn, hoặc dùng scope chính xác ở cùng cấp.

Debug: +UVM_CONFIG_DB_TRACE hiện từng bản ghi và ai thắng.

drain được set bằng int unsigned nhưng driver get bằng int. Điều gì xảy ra? Làm sao phát hiện?

get trả 0 (không tìm thấy), driver giữ giá trị mặc định, không có lỗi/warning. Phát hiện: (1) kiểm tra giá trị trả về của get và uvm_info khi fail; (2) +UVM_CONFIG_DB_TRACE thấy “read: … not found”; (3) in giá trị thực dùng trong end_of_elaboration_phase. Quy ước dự án: dùng config object thay vì các field rời để tránh cả họ lỗi này.

ACTIVE và PASSIVE khác nhau ở đâu? Khi nào dùng PASSIVE?

ACTIVE: agent tạo sequencer + driver (và monitor) — tự kích thích DUT. PASSIVE: chỉ monitor. Dùng PASSIVE khi stimulus đến từ nơi khác: DUT đã được agent khác/firmware thật lái; hoặc vertical reuse — agent dùng ở block-level là ACTIVE, lên system-level thì PASSIVE quan sát interface nội bộ.

if (cfg.is_active == UVM_ACTIVE) begin
  sqr = riscv_sequencer::type_id::create("sqr", this);
  drv = riscv_driver   ::type_id::create("drv", this);
end
Config object so với đặt từng field vào config_db — ưu nhược?

Object: một chỗ set/get, dễ mở rộng, có thể randomize, tự mô tả (print/copy). Từng field: không cần định nghĩa class, nhưng mỗi tham số một cặp set/get, dễ lệch kiểu/tên, khó thấy toàn cảnh. Thực tế: config object cho agent/env; field rời chỉ cho thứ thật sự nhỏ (verbosity, vif). Lưu ý handle chia sẻ — nếu một component sửa cfg, cả cây thấy.

Phase kết thúc khi nào? Nếu test không raise objection thì sao?

Khi tổng objection = 0 (+ drain_time). Nếu test không raise gì, run_phase kết thúc ngay ở time 0: các forever của driver/monitor bị kill, báo cáo cuối in 0 retire, test “PASS” rỗng — lỗi nguy hiểm. Phòng: assertion cuối test “đã có ≥ N giao dịch” trong check_phase, và luôn có +UVM_TIMEOUT.

uvm_test_top là gì? Vì sao set vif theo đường dẫn đó?

Tên instance mặc định của test do run_test() tạo (con của uvm_top). set(null,"uvm_test_top","vif",vif) khớp với get(this,"","vif") khi this là test. Env/agent có đường dẫn dài hơn (uvm_test_top.env.agent.drv) nên không khớp chính xác — vì thế bản lab để test get rồi nhét vào cfg.vif. Muốn mọi component nhìn thấy trực tiếp: set(null,"uvm_test_top.*","vif",vif).

Factory registry thật sự lưu gì? Điều gì xảy ra nếu một lớp quên `uvm_component_utils?

Lưu ánh xạ tên → proxy (uvm_component_registry) với hàm create_component. Quên macro: (1) T::type_id không tồn tại → lỗi compile khi gọi type_id::create; (2) nếu dùng new() thì chạy nhưng không override được và run_test("T") báo UVM_FATAL INVTST “requested test not found”. Kiểm tra bằng uvm_factory::get().print().

13. Cheat-sheet

agent.build: get cfg; create mon(+set vif); if ACTIVE create sqr,drv(+set vif,drain)
agent.connect: if ACTIVE drv.seq_item_port.connect(sqr.seq_item_export)
env.build: get cfg; create agent; set cfg to agent
test.build: create cfg; get vif; create env; set cfg to env
top: set vif(uvm_test_top); run_test("riscv_base_test")

14. Bài tập code & câu hỏi nâng cao UVM

8 bài rèn tay, tăng dần độ khó. Làm trên baseline của lab này; đáp án chỉ là hướng tham khảo — giá trị nằm ở việc bạn tự gõ, chạy và đọc log.

0 / 8 bài đã làm
★ Dễ

EX1 — In cây và factory

Thêm end_of_elaboration_phase trong test: uvm_top.print_topology(); uvm_factory::get().print(); Chỉ ra component nào là riscv_sequencer (typedef!) và nó hiện tên gì.
Gợi ý & đáp án tham khảo

Vì typedef uvm_sequencer#(riscv_seq_item) riscv_sequencer; không phải class mới, type name hiện là uvm_sequencer #(riscv_seq_item). Muốn tên đẹp và get_type_name đúng thì khai class thật class riscv_sequencer extends uvm_sequencer#(riscv_seq_item); `uvm_component_utils(...) — như bản AXI.

★ Dễ

EX2 — Bẫy ưu tiên config_db

Trong test set(this,"env.agent.drv","drain",20) và trong agent set(this,"drv","drain",cfg.drain). Driver thấy giá trị nào? Đổi vai trò (test set sau agent) có khác không? Xác nhận bằng +UVM_CONFIG_DB_TRACE.
Gợi ý & đáp án tham khảo

Test ở cấp cao hơn → test thắng (20), bất kể thứ tự thời gian. Đây là cơ chế cho phép test ghi đè mặc định của env/agent.

★★ Vừa

EX3 — Kiểu sai kiểu — im lặng

Đổi get của drain thành int. Chạy và chứng minh không có lỗi nào. Sau đó thêm guard in `uvm_warning khi get fail và xem log.
Gợi ý & đáp án tham khảo

Đây là bài kinh điển: kết quả “chạy đúng” nhưng DRAIN mặc định thay thế cấu hình. Guard + trace là hai công cụ bắt lỗi.

★★ Vừa

EX4 — Agent PASSIVE & firmware thật

Đặt is_active=UVM_PASSIVE. Viết test khác nạp ROM bằng vif.load_hex(...) rồi nhả reset từ test (không qua driver). Chứng minh monitor vẫn quan sát retire.
Gợi ý & đáp án tham khảo

Đây chính là mô hình Lab 15 (firmware). Chú ý: khi driver không tồn tại thì ai điều khiển reset? Test phải làm — và phải làm trong run_phase có objection.

★★ Vừa

EX5 — Config object randomizable

Thêm vào riscv_agent_config các field rand int unsigned drain; rand bit en_cov; và constraint drain inside {[8:16]}. Test randomize cfg trước khi set. Chạy 5 seed, ghi lại drain thực dùng.
Gợi ý & đáp án tham khảo

Config-space randomization: mỗi seed một cấu hình → mở rộng coverage ở mức môi trường. Nhớ cfg.randomize() trước khi set, và in cfg.sprint() để tái lập.

★★ Vừa

EX6 — Timeout & objection debug

Cố ý để một component raise objection mà không drop (ví dụ driver). Chạy với +UVM_OBJECTION_TRACE và +UVM_TIMEOUT=5000,NO. Chụp log để chỉ ra ai giữ objection.
Gợi ý & đáp án tham khảo

Log trace in raised/dropped kèm đường dẫn component và mô tả → tìm được thủ phạm. Watchdog sinh UVM_FATAL PH_TIMEOUT.

★★★ Khó

EX7 — Hai agent, một env

Tạo agent_a (ACTIVE) và agent_b (PASSIVE) cùng class, mỗi cái có cfg riêng. Dùng scope "agent_a"/"agent_b" để set. Viết tại sao scope "*" sẽ làm hỏng bài này.
Gợi ý & đáp án tham khảo

Với "*", cả hai nhận cùng cfg (hoặc cái nào set sau), nên is_active của agent_b bị ghi đè — lỗi cấu hình kinh điển trong env nhiều agent.

★★★ Khó

EX8 — Đảo build/connect (có chủ đích)

Chuyển dòng drv.seq_item_port.connect(...) từ connect_phase sang cuối build_phase của agent. Có chạy không? Rồi đặt nó trước dòng tạo sqr. Giải thích kết quả bằng thứ tự phase.
Gợi ý & đáp án tham khảo

Ở cuối build thì thường vẫn chạy vì sqr/drv đã tạo; trước khi tạo thì null → fatal. Nhưng nối port trong build vi phạm quy ước (đầu kia ở cấp dưới có thể chưa tạo ở env phức tạp) — một lỗi ẩn chỉ xuất hiện khi hierarchy sâu hơn.
